# garage_recon：多层车库车载 3D 重建、自动语义标注与导航地图

用车载（或手持）LiDAR、IMU、轮速和相机：
- 重建多层车库，精度达到测量级；
- 自动标注语义，包括结构、标线、车位、车位号和车辆；
- 生成导航能直接用的地图：车位地址、目标位姿、不穿墙的路网。

自带合成车库数据生成器，整条链路不依赖真实数据也能跑通和量化评测。合成数据包括：
- 场景：两层 + 坡道，停放车辆和移动车辆；
- 传感器：车载 LiDAR、鱼眼、IMU、轮速；
- 真值，以及模拟的手持扫描。

已试跑的真实数据：
- FusionPortableV2：地下车库（手持）和室外停车场（无人车）；
- Skierniewice 地下车库：Mandeye 手持扫描，带 TLS 真值；
- Oxford Spires Keble College：户外手持，带 TLS 地图和真值轨迹；
- Hilti 2021 Parking Deck：手持，带全站仪真值。转换已核对，内置里程计在这条序列上发散（见 9.7）。

## 2. 原则与总体数据流

1. **几何是骨架，必须达到测量级。** 位置和尺度由 LiDAR + IMU 决定。DA3 和 3DGS 只补 LiDAR 没测到的细节和外观，不得移动 LiDAR 已测的表面。
   - **现状**：
     - 合成数据达到测量级：检查点 RMSE 0.5 cm，表面 p95 1.6 cm；
     - 真实数据还没有：Skierniewice 表面 p95 5.2 cm，门槛 3 cm（9.0）；
     - "不移动已测表面"做到了：LiDAR 锚定的高斯离地图中位 0.4–0.5 cm，DA3 只填空洞。
2. **所有数据共用一套位姿。** 以下数据都从同一个位姿集合取位姿：LiDAR 点、每台相机的每一行像素、DA3 输入、3DGS 训练视角、语义渲染、占据、矢量（见 4.2）。
   - **现状**：做到。每个产物记录所用的位姿集合（`provenance`），过期产物由自检拒收。
3. **语义分三路**（5.2）：
   - 2D 视觉大模型（SAM、CLIP / SigLIP、OCR）负责认出"是什么"；
   - 3D 表示负责跨视角一致和实例身份；
   - 几何规则负责约束和校验。
   - **现状**：
     - 真实数据上在产出的是两部分：几何规则（结构、标线、车位、车辆），加 2D 检测（`objects2d`：灯、标志牌、减速带、道闸、消防设施，抬到 3D 并做几何校验）；
     - SigLIP 2 零样本分类在真实车库上不可用（与几何标签只有 12% 一致），语言路线还没有在真实数据上产出（见下表 D、5.2）。
4. **导航的障碍按几何判定。** 车辆高度带内的静态点都是障碍；语义类别只用于分层，类别分错不能让路线穿墙。
   - **现状**：做到。合成数据和两份真实数据上，碰到障碍的路线都是 0（9.4）。
5. **核心几何算法全部在 C++。** Python 只负责读写文件、把配置映射到 C++ 配置结构，以及按阶段编排。
   - **现状**：骨架做到了。楼层 / 坡道、结构、标线、亚像素矢量拟合、车位推断还是 Python（numpy）实现（10.1），待移到 C++。

```
采集（LiDAR / IMU / 轮速 / 相机）
  │
  ▼
[A] 骨架（C++）：里程计 → 回环 → 位姿图（IMU 预积分）+ LiDAR BA → 连续时间轨迹 → 相机标定 → 测量点云
  │   输出：唯一的位姿集合（pose_set_id）
  ▼
[B] DA3：位姿条件的多视角深度 → 与 LiDAR 对齐 → 稠密深度先验
  ▼
[C] 3DGS（gsplat + 3DGUT）：LiDAR 锚定，鱼眼 + 卷帘快门 → 核验 → 表面、正射影像、任意视角渲染
  ▼
[D] 2D 基础模型：SAM 2 掩膜、SigLIP 2 / CLIP 嵌入、OCR、DINO 稠密特征
  ▼
[E] 身份关联（几何投影 + DINO）→ 身份级语言特征 → 3D 类别与实例
  ▼
[F] 规则与矢量化、逐帧标签、占据、车位号 → 导航地图 → 导出与 QA
```

**各阶段现状**（2026-10-22）

| 阶段 | 现状 | 详见 |
|---|---|---|
| A 骨架 | 已实现，在 5 份真实数据上实测。图优化后 ATE：Keble 5.6 cm，FusionPortable 地下车库 0.14 m，Hilti 0.34 m | 4、9.0 |

## 3. 使用

### 3.1 构建

依赖：
- 必需：CMake ≥ 3.18、C++17 编译器、Eigen3、Python ≥ 3.9（numpy、scipy、pyyaml、opencv、scikit-image、shapely）；
- 可选：libomp（OpenMP）、laspy + lazrs（LAS / LAZ 读写，Mandeye 转换）、rosbags（ROS bag 转换）。

```bash
python3 -m venv --system-site-packages .venv && .venv/bin/pip install pybind11 scikit-build-core "laspy[lazrs]" rosbags pytest
cmake -S . -B build -DPython_EXECUTABLE=$PWD/.venv/bin/python && cmake --build build -j8
./build/gr_tests                      # C++ 单元测试 + 纯 C++ 端到端（约 15 秒）
PYTHONPATH=python .venv/bin/python -m pytest -q   # Python 测试（含一次 tiny 端到端，约 40 秒）
```

开发模式下，扩展模块直接生成到 `python/garage_recon/`。也可以用 `pip install .`（scikit-build-core）安装成包，安装前先删掉源码目录里的 `_core*.so`。

> macOS 注意：部分 Command Line Tools 安装只在 SDK 里带了 libc++ 头文件，clang 会报 `'vector' file not found`。CMakeLists 已自动检测并改用 SDK 中的头文件；重装 Command Line Tools 也能解决。

**代码风格**
- **C++** 遵循 [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html)：
  - 函数 / 类型用 CamelCase，变量用 snake_case，类成员带下划线后缀；
  - 位姿命名为 `a_from_b`（如 `world_from_lidar`）；
  - `#define` 头文件保护，80 列；
  - 格式由 `.clang-format`（Google 风格）统一：`find cpp \( -name '*.h' -o -name '*.cc' \) -print0 | xargs -0 clang-format -i`。
- **错误处理**：核心库不使用异常（以 `-fno-exceptions` 编译）。
  - 违反前置条件属于编程错误，由 `GR_CHECK` 报告后终止；
  - 可能"正常失败"的操作返回 `std::optional`；
  - Python 绑定在调用核心库之前校验输入，并转换成 `ValueError` / `IndexError`。pybind11 本身依赖异常，所以只有绑定层使用异常。
- **Python**：新写和改动的模块遵循 [Google Python Style Guide](https://google.github.io/styleguide/pyguide.html)：
  - 80 列；
  - 只导入模块（`typing` 除外），不用相对导入；
  - 模块、类和公开函数都有 docstring。

### 3.2 快速开始

```bash
# 一条命令：生成合成车库 → 重建 → 语义 → 自检 → 评测
PYTHONPATH=python .venv/bin/python -m garage_recon.cli demo --out out/tiny --preset tiny

# 分步（small = 两层 + 坡道 + 两趟）
PYTHONPATH=python .venv/bin/python -m garage_recon.cli synth --out data/small --preset small
PYTHONPATH=python .venv/bin/python -m garage_recon.cli recon --trips data/small/trip_00 data/small/trip_01 --work work/small --gt data/small/gt
PYTHONPATH=python .venv/bin/python -m garage_recon.cli semantics --trips data/small/trip_00 data/small/trip_01 --work work/small --gt data/small/gt
PYTHONPATH=python .venv/bin/python -m garage_recon.cli qa --trips data/small/trip_00 data/small/trip_01 --work work/small
PYTHONPATH=python .venv/bin/python -m garage_recon.cli eval --work work/small --gt data/small/gt
PYTHONPATH=python .venv/bin/python -m garage_recon.cli accept --work work/small --handheld data/small/handheld
```

- `--stages`：只跑部分阶段，各阶段可重复执行。
- `--config my.yaml`：覆盖默认参数（`python/garage_recon/default_config.yaml`）。
- `--gt`：让模型接口使用合成数据的真值实现（`models.backend: auto`）。不给 `--gt` 又没有接真实模型时，相机标定和语言路线会跳过。
- `synth`：
  - `--ideal` 生成没有传感器误差的数据：无零偏、全局快门、时间偏差为 0、外参准确；
  - 同时生成模拟的手持扫描真值（`data/small/handheld/`），`--no-handheld` 跳过；已有数据可用 `handheld --data DIR` 补生成。
- `accept`：把重建配准到手持真值并出验收报告（`work/small/acceptance/report.md`），见第 7 节。

### 3.3 查看器（`viewer`）

```bash
PYTHONPATH=python .venv/bin/python -m garage_recon.cli viewer \
    --work work/a work/b --name "停车场" "车库" --out viewer --serve 8765
# 浏览器打开 http://localhost:8765/
```

- **导出内容**：每个重建目录导出成一个数据集，包括：
  - 地图点：体素抽稀到最多 `--max-points` 个，坐标量化到 1 cm；
  - 每点属性：反射强度、趟次、语义类别、动态 / 跨趟变化、σ、离地高度；
  - 各趟轨迹；
  - 车位、标线、柱和墙的矢量；
  - 路网和车位目标点；
  - 全分辨率的 `files/map.ply`（带全部属性）和各趟 TUM 轨迹，可在 CloudCompare 等工具里打开。
- **查看器**：three.js 加 GPU 着色器，数百万点也流畅。
  - 操作：左键拖动旋转，右键或 Shift + 左键平移，滚轮在光标处缩放，双击把点击处设为旋转中心；另有俯视 / 斜视 / 复位按钮。
  - 着色：高程、反射强度、趟次、语义类别、点位精度 σ、动态 / 变化。
  - 离地高度上下限：可以去掉顶板，看清车库内部。
  - 图层：轨迹、车位、标线、柱与墙、路网与车位目标点，可分别开关。
  - 导航：输入地址（如"L1 B区 9号"）或车位编号，从入口规划并画出路线和停车朝向。
- **打开方式**：要通过 HTTP 打开（`--serve`，或任意静态文件服务）。浏览器不允许页面直接读取本地文件。

### 3.4 输入：一趟数据的目录格式

```
<trip>/meta.yaml            trip_id、garage_id、可选 initial_pose（入口处 INS 位姿，world←vehicle）及其时间戳 initial_pose_time（缺省为第一帧 LiDAR 时刻）
<trip>/rig.yaml             LiDAR / 相机内外参（T_vehicle_sensor）、相机时间偏差与卷帘行时间、IMU 外参、轮速比例
<trip>/lidar/<name>/<ns>.npz   points (N,3) 传感器坐标、intensity、time（相对帧时间戳的秒数，≤0）
<trip>/cameras/<name>/<ns>.jpg
<trip>/imu.csv  wheel.csv  gnss.csv
```

- **相机时间约定**：时间戳为 t 的图像，第 r 行在 t + time_offset + r × rolling_shutter_line_time 曝光。行时间来自传感器手册；时间偏差和外参由 calibration 阶段估计。
- **LIO**：内置 LiDAR-惯性里程计用 `odometry.use_lio` 打开；FAST-LIO2 / FAST-LIVO2 等外部轨迹可通过 `odometry.external_trajectory` 接入，替代内置里程计。

### 3.5 真实数据：ROS bag / Mandeye 转换与扫描导入

**`convert`：ROS bag 或 Mandeye 记录 → trip**

```bash
PYTHONPATH=python .venv/bin/python -m garage_recon.cli convert \
    --bag rec.bag --profile python/garage_recon/convert/profiles/fusionportable_v2_handheld.yaml \
    --out data/real/trip_00 [--start 0 --duration 60]

# Mandeye 手持扫描仪（Livox + 内置 IMU，不经 ROS）的原始分块目录
PYTHONPATH=python .venv/bin/python -m garage_recon.cli convert \
    --mandeye UndegroundParkingDataset/mandeye \
    --profile python/garage_recon/convert/profiles/mandeye_mid360_skierniewice.yaml \
    --out data/real/skierniewice/trip_00
```

- **读包**：用纯 Python 的 `rosbags` 读 ROS 1 bag 和 ROS 2 bag（sqlite3 / mcap），不需要装 ROS。
  - `--jobs N`：按 bag 时间切成 N 段，由 N 个进程并行读取；扫描和图像由各进程直接写入，IMU 等行数据由主进程合并。
  - bz2 压缩的 bag 单进程只能解压约 20 MB/s，这时提速明显：Hilti Parking_1（29 GB）单进程约 65 分钟，`--jobs 12` 用 4.8 分钟。
  - 限帧率的相机在每段开头重新计间隔，段边界处最多多出一张图。
- **转换配置（profile，YAML）**写明以下内容，说明见 `convert/profile.py`：
  - 话题；
  - 各传感器相对一个参考传感器的外参：4×4 矩阵，或四元数 + 平移，`invert: true` 表示文件里写的是反方向；
  - 相机内参：以标定时的分辨率给出，可按 `scale` 缩小，内参随之缩放；
  - 各数据流到 IMU 时钟的时间偏差：相机的写进 rig.yaml，由标定阶段细化；
  - 车体坐标系放在参考传感器的什么位置。
- **各数据流的转换**：

  | 数据 | 消息类型 | 处理 |
  |---|---|---|
  | LiDAR | `PointCloud2` | 按字段表解码，支持有组织点云和行填充；每点时间换成相对扫描结束时刻的秒数；按距离裁剪 |
  | IMU | `Imu` | 写成 imu.csv，保持 IMU 自身坐标系 |
  | 轮速 | `TwistStamped` / `Odometry` / `JointState` / `Float` | 写成 wheel.csv；也支持编码器累计脉冲（`kind: joint_position`，中心差分求速度） |
  | GNSS | `NavSatFix` | 转成局部 ENU 坐标 |
  | 相机 | `Image` / `CompressedImage` | 可降采样、限帧率 |
  | INS | `Odometry` | 取第一帧时刻的位姿作为入口位姿（`initial_pose` 与 `initial_pose_time`） |
- **车体坐标系**：流程假定车体原点在地面上（楼层与自车扫过区域依赖它），且没有 INS 位姿时世界坐标系就是起步时的车体坐标系，IMU 因子要求它重力对齐。IMU 因子和 LIO 在 IMU 所在点积分（rig.yaml `T_vehicle_imu` 的平移），车体原点离 IMU 多远都可以。
  - 不是车的平台（手持、背包）没有天然在地面上的车体坐标系：
    - `vehicle.level: true` 用起步静止时 IMU 测到的重力把 z 轴摆正；
    - `vehicle.floor: auto` 用参考传感器下方的地面（C++ RANSAC 平面）把原点放到地面上。
  - 车：`vehicle.reference_xy` 可把车体原点放到后轴，即横向速度为零的点。
- **LiDAR 时钟按每段录制估计**（`lidars.<name>.clock_sync`）：
  - 用雷达自带的 IMU（与点云同一时钟）和主 IMU 的陀螺分窗口互相关（C++ `EstimateClockOffset`，每个窗口同时求两 IMU 间的旋转），逐帧修正点云时间戳；
  - 模型可选分段线性（`piecewise`，默认）或"偏差 + 线性漂移"（`linear`）；
  - `imu_delay` 是雷达 IMU 相对点云的固定延迟，属于雷达型号的常数（OS1-128：−22 ms）；
  - 估计结果写进 meta.yaml。
  - 这个偏差不是常数：FusionPortableV2 四段录制里，Ouster 时钟相对 STIM300 差 2–82 ms，一段 400 s 的录制里还漂移了 13 ms。
- **Mandeye 记录**（`convert/mandeye.py`）：
  - 输入是编号分块（每块 10–20 s）：`lidarNNNN.laz`（LiDAR 坐标系的点，`gps_time` 为设备时钟）和 `imuNNNN.csv`（ns、rad/s、g）；
  - 连续点流按 `sweep_duration` 切成扫描帧，跨分块的帧会接上；
  - 配置沿用上面的格式，话题处写分块文件前缀（`lidar`、`imu`）；读 LAZ 需要 `laspy[lazrs]`。
- **摆正与放到地面**（`convert/frames.py`）：两个转换器共用上面 `vehicle.level` / `vehicle.floor` 的逻辑。
- **自带配置**（`convert/profiles/`）：

## 4. 重建

### 4.1 阶段

| 阶段 | 做法 | 输出（work/） |
|---|---|---|
| odometry | 逐帧点到面 ICP（约 15 ms/帧）；扫描时间窗内的陀螺 + 轮速逐点积分去畸变，同时作为配准初值。有 IMU 的设备在几何退化处可改用 LiDAR-惯性里程计（`odometry.use_lio`：迭代误差状态卡尔曼滤波，IMU 传播 + 点到面更新）。按距离 / 角度选关键帧并保存去畸变点云 | `trips/<trip>/odometry.tum`、`kf/` |
| graph | 位姿图 = 各趟里程计链 + 回环 + 入口锚点（INS 位姿 / GNSS，按各自时间戳推到关键帧）+ **IMU 预积分因子**（每个关键帧带速度与零偏）+ 轮速车体速度因子 + 零偏随机游走。**没有锚点的趟次**（手持等，各自以起点为原点）先整趟粗对齐到已放置的趟次上（见下）。回环候选按位置半径和楼层高差门控，Scan Context 排序，多尺度 ICP 验证，PCM 剔除不一致回环；有相机时还可以加 DINO 外观候选（不需要位姿初值，8.4）。最后做 **LiDAR BA**（见下） | `graph/`（含每个关键帧的速度与零偏、BA 每轮统计）、`trips/<trip>/poses.tum` |
| trajectory | 生成**位姿集合**：每趟一条连续时间轨迹（全部激光帧位姿为节点，节点间用去零偏陀螺和轮速），加上 rig 标定，带内容哈希 `pose_set_id`；用最终轨迹重新去畸变全部关键帧点云 | `pose_set/`、`trips/<trip>/kf_final/` |
| calibration | 每台相机：锚点图像的查询点匹配到后续若干帧（DINO / RoMa 类匹配器，合成数据用真值实现），形成多视图轨迹；在固定轨迹上联合估计时间偏差和外参，路标约束在 LiDAR 面上；不达标的相机保留 rig.yaml；结果写成新版本的位姿集合 | `calibration.json`、`pose_set/` |
| map | **测量点云**：5 cm 体素，只取 20 m 内的回波；同一体素内与最近观测距离相当的观测按 1/σ² 加权平均，σ 随距离增大；每点带沿法向的 σ 与观测次数；另算法向。**楼层 / 坡道**：以车辆轨迹为主识别，每层地面高度栅格取中值并排除坡道。**动态点**：距离图像可见性投票，按趟统计，区分"本趟内移动"和"跨趟变化"，再加自车扫过区域必为空闲的约束 | `map/point_map.npz`、`levels.json` |
| bev | 每层地面强度、地面高度、物体高度栅格 | `bev/level_<i>.npz` + PNG |
| texture | 四路鱼眼投影到地面网格（每一行按曝光时刻取位姿），每格取最佳视角（近、俯视、未被遮挡），中值融合去高光 | `bev/level_<i>_rgb.png` |

**无锚点趟次的粗对齐**（`trip_align`，C++ `AlignTrips`）：在回环检测之前，把没有入口位姿的趟次放进同一坐标系。
1. **参考**：有锚点（INS / GNSS）的趟次定义世界坐标系；都没有锚点时，取第一趟。
2. **配准**：按趟次顺序，把这一趟在当前位姿下的关键帧地图配到已放置趟次的地图上：
   - 重力对齐的粗搜索给出候选（`AlignGravityAlignedCandidates`）：墙面方向给出四个航向，立面占据图相关定平移；水平面高度相关的每个峰给一个高程，布局相同的楼层每隔一个层距就有一个峰；
   - 每个候选做一次多尺度 ICP，最多检验 8 个。
3. **接受**：最优解的 ICP 吻合度 ≥ 0.5、残差 ≤ 20 cm，并且比任何不同的解（相差 1 m 或 5° 以上）的吻合度至少高 0.03。分不清时不放置，日志记为 ambiguous。
4. **应用**：接受后，平移这一趟所有关键帧的初值，并把它的弱先验移到对齐后的位置（2 m / 5°），再重新做一次不带回环的优化。之后跨趟回环能按位置门控找到候选。

**LiDAR BA**（`plane_factor`、`lidar_ba`）：所有关键帧位姿一起优化，让各帧扫到的同一平面重合。
1. **提取平面**：5–30 m 的回波用自适应八叉树切成约 1 万个平面，每个平面最多被 20 个关键帧观测；边角处的体素继续切分，不让两个面混在一起。5 m 内的回波不用（见 4.3）。
2. **代价**：每个平面存各关键帧点的一阶、二阶矩，平面参数用 Schur 补消去，代价为 BALM 式的 W·λ_min。
3. **求解**：平面因子与上表的全部因子联合 LM 优化。位姿块稠密求解（先消去惯性状态），"重新提取平面 + 优化"共 2 轮。
4. **作用**：BA 取代了"扫描到地图精修"。精修仍保留为可选项（`refine`，BA 关闭时用）。

### 4.2 位姿集合：一套位姿的工程保证

- **内容**：以下参数作为一个整体，带版本号 `pose_set_id`：
  - 连续时间轨迹 world_from_vehicle(t)；
  - 各传感器外参；
  - 时间偏差；
  - 卷帘行时间。
- **只从这里取位姿**：trajectory 之后的所有阶段只从位姿集合取位姿（相机每一行按曝光时刻取，`CameraExposure`），并在 `provenance.json` 记录所用版本。
- **修正只回到位姿图**：标定残差或（将来的）3DGS 光度残差发现的位姿 / 标定问题，只能作为因子回到位姿图，重新求解并生成新版本。任何模块不得私自优化位姿。
- **版本一致**：
  - 只依赖 LiDAR / IMU 的阶段比较 `trajectory_id`，用到相机的阶段比较完整的 `pose_set_id`；
  - 自检列出用旧版本生成、需要重跑的阶段。

### 4.3 关键经验

前几条在合成数据上验证，最后四条来自真实数据。

- **点到点 ICP 在稀疏线束下会偏向"零运动"**：地面、顶板、墙面上的扫描环在原位置对得最好。改为多尺度点到面并跳过孤立的单环线段后，单次配准误差从 0.36 m 降到毫米级。
- **坡道相连的楼层需要重力约束**：没有重力约束时，下坡引入约 1° 的俯仰误差，整层地图倾斜，下层高程偏差约 0.3 m，回环修不掉。
  - 加计零偏会把重力方向带偏：0.065 m/s² 约偏 0.4°，坡道相连的两层因此相对倾斜。
  - IMU 预积分因子带每个关键帧的速度和零偏，可以把零偏一起估出来，零偏误差 < 0.002 m/s²。
- **去畸变要用 IMU，不能用帧间平均角速度**：转弯时两者差别很大。改用扫描时间窗内的陀螺积分后，里程计最大旋转误差从 3.5° 降到 0.7°。
- **IMU 噪声要用"等效值"**：
  - 噪声密度设成传感器白噪声时，IMU 的系统误差会把轨迹拉弯，最大姿态误差 0.5°。仿真中的系统误差是半个采样的时间错位和数值微分。
  - 陀螺 0.01 rad/s/√Hz、加计 0.2 m/s²/√Hz 时最好；放大到 300 倍又会丢掉横滚 / 俯仰约束。
  - 实车按 Allan 方差加放大系数标定。
- **轮速的非完整约束要放宽**：车体坐标系与运动方向并不严格一致（转弯、坡道衔接、侧滑）。侧向 / 垂向速度 σ 从 0.05 放宽到 0.3 m/s 后，ATE 从 3.9 cm 降到 2.2 cm，地图 p90 从 3.4 cm 降到 2.0 cm。
- **扫描到地图精修会收敛到"自洽但有偏"的解**：
  - 坡道两端，地面与坡面相交成折线。局部平面拟合把两个面混在一起，把坡度"拉平"约 0.05°，两层的相对高程差约 2 cm。
  - 只看地图厚度、回环残差等内部指标发现不了，要靠手持真值或控制点。
  - BA 的八叉树把折线处的体素切开，再与 IMU 因子联合优化后，柱检查点的两层高程偏差从 −0.8 / +0.9 cm 降到 ±0.1 cm。
- **BA 要用远处的回波**：均匀的坡道通道在行驶方向上几乎没有约束。BA 只用 20 m 内的回波时，两层沿坡道方向错开约 2 cm；改为 30 m 后，刚体对齐后的 ATE 从 1.0 cm 降到 0.4 cm。
- **刚性的地图会放大锚点的错误**：BA 后整张图像一块刚体，入口锚点的时间错误不再被局部吸收，而是把整张图转偏约 0.2°。
  - 错误来源：INS 位姿早于第一帧 0.1 s 却挂在第一帧上；早于第一帧的 GNSS 也被钳到第一帧；第一帧因浮点舍入没有去畸变。
  - 修法：锚点带时间戳，用轮速 / 陀螺推到关键帧时刻；IMU 先验在边界外允许保持边界值 0.1 s；连续轨迹首尾外推 0.2 s。
- **地图只用近处回波，并融合多次观测**：
  - 掠射角下，0.3° 的姿态误差会让 25 m 外的地面点偏 10 cm 以上。限制在 20 m 内并让近处观测优先后，地图 p90 误差从 23 cm 降到 2 cm。
  - 同一体素只留最近一次观测时，地图噪声就是测距噪声。把距离相当的观测按 1/σ² 加权平均后，配准后的表面误差中位从 0.37 cm 降到 0.22 cm。每点的 σ 基本可信：约 79% 的误差在 1σ 内，94% 在 2σ 内。
- **动态点要按趟、按目标判断**：逐点投票对移动车只覆盖约一半的点，后来再没被观测到的部分没有证据。按聚类整体判定后，移动车拖影能被完整清除。
- **相机时间偏差是"等效"参数**：
  - 1.4 m/s 时，沿行驶方向 1 cm 的轨迹误差相当于 7 ms。
  - 用真值轨迹标定时无偏；用估计轨迹时会吸收轨迹误差：轨迹 ATE 6.8 cm 时偏差约 5 ms，2 cm 时 ≤ 2 ms。
  - 测量级相机几何仍需硬件同步（PTP / 触发）。
- **绝对坐标要靠控制点**：车辆坐标系的绝对位置只由入口锚点决定，误差约 1–2 cm、0.03°。测量级成果按测量惯例先用控制点定坐标系，再看检查点。
- **BA 不用 5 m 内的回波**（真实数据，9.5、9.6）：手持数据上 BA 曾把地图竖向压弯。
  - **现象**：Skierniewice 车库 85 m 的往返走廊，两端被压低 20 cm、中段抬高 5–10 cm，呈拱形；水平面误差 p95 从 4 cm 变成 21 cm。FusionPortableV2 手持数据上是 400 m 走廊 ±2 m。
  - **排除**：
    - 远处掠射的地面：BA 只用 10 m 内的回波、或按距离和入射角降权（`ba.angular_sigma`）后，弯得更厉害；
    - IMU：去掉 IMU 因子无变化；
    - 收紧 IMU 噪声：地面变好，但墙面 p95 变成 20–25 cm；
    - 里程计因子收紧 4 倍：无变化；
    - LiDAR–IMU 时间偏差：±20 ms 扫描无效。
  - **原因**：用较准的位姿对照 TLS，逐帧残差在传感器系里都在 1 cm 内。唯一的系统偏差在近处：顶板只比传感器高 0.6 m，在 1.5–5 m 处读数偏短 0.4–0.8 cm，且越近越偏。近处回波点最密，在平面里权重最大。长走廊竖向弯曲这个模态的约束极弱，毫米级的偏差就能把走廊两端压弯 20 cm。
  - **修法**：`ba.min_range` 从 1 m 改为 5 m（新默认）。
    - Skierniewice：水平面 p95 4.4 cm，竖直面 p95 6.3 cm（不带 BA 时 4.2 / 7.8 cm）；
    - Spires keble-02：ATE 7.0 cm（不带 BA 7.1，旧 BA 9.1）；
    - 合成车库：联合 ATE 0.43 cm（旧值 0.44），检查点 RMSE 0.42 cm（旧值 0.45）。
  - **敏感度**：4–6 m 都可以；8 m 时平面太少，又会变差。
- **转换时帧的时间只能用有效回波**（真实数据，9.7）：Ouster 无回波像素的 `t` 字段可能是任意值，一个这样的像素就能把整帧的时间戳推迟 4 s。里程计在这一帧上跑飞，看起来却像几何退化。判断"退化"之前，先查原始数据的帧间隔和逐点时间范围。
- **IMU 要在它所在的点积分**（真实数据，9.6）：
  - 手持配置的车体原点在地面上，IMU 在其上方 1.8 m。在车体原点积分时，手的转动被当成了加速度。
  - 合成车载数据的 IMU 就在车体原点，所以一直没暴露。
  - 修正后：Keble ATE 从 7.5 cm 降到 5.6 cm，Hilti 从 1.03 m 降到 0.34 m。
- **LIO 的 IMU 噪声宁松勿紧**（真实数据，9.7）：手持设备振动大；噪声给得过紧时，退化路段里 IMU 预测会压过 LiDAR 的弱约束，速度跑飞。
- **单程直线采集时，加计零偏与倾斜分不开**（真实数据）：消费级零偏先验（0.2 m/s²）下，零偏被估成 0.5 m/s²，整条路线倾斜 3%。战术级 IMU 要用相应的先验（0.03 m/s²）。
- **没有入口位姿的多趟数据要先粗对齐**（真实数据，9.6）：回环候选按当前估计位置门控，两趟各自以起点为原点、朝向差 76° 时，找不到跨趟回环。整趟粗对齐（`trip_align`）之后，两趟重复精度中位 4.8 cm，与用真值设入口位姿时相同。
- **布局重复的楼层要逐个检验候选**（合成数据，9.6）：粗搜索的最优高程可能差一层，ICP 吻合度也会饱和（错开一个柱距仍有 95% 的点对得上）。所以每个航向、高程候选都用 ICP 检验，要求最优解比任何不同的解至少多对上 3% 的点，分不清就不放置。

## 5. 语义标注

### 5.1 阶段

| 阶段 | 做法 | 输出（work/semantics/） |
|---|---|---|
| structure | 地面 / 坡道 / 顶板 / 机电按高度与法向标注。**柱**：多高度切片都占据、且到达最高切片的紧凑块，碎片合并；在地图点上拟合各柱面（法向朝外的点的中位位置），看不到的一侧按典型柱宽补全；按柱网聚类生成轴号。**墙**：沿网格方向的直线段，要求薄，且到顶或长于一辆车（避免把车侧面当墙） | `labels.npz`、`structure.json` |
| markings | **检测**：每层 LiDAR 强度图 + 鱼眼地面纹理：分层白顶帽、稳健阈值、沿网格方向先闭后开（连接激光环采样的虚线）、骨架化、拟合直线、共线合并；要求线两侧都是已观测地面且与网格对齐。**亚像素重测**（正射影像亮度图）：横向剖面的半亮度边缘定中心线（稳健直线拟合），沿线的半亮度交点定端点；端点外侧地面被观测到才算"可靠端点"（车、墙根、柱旁的端点不可靠） | `markings.json/.geojson` |
| slots | **分排**：隔线分排，排内相邻隔线成车位；每排按隔线端点估计自身方向（排与柱网常差 1–2°，要过显著性门槛），在排自己的坐标系里组装。**推断**：被车挡住的隔线按整数倍宽度推断，但要有理由：假想隔线落在看得清、没有车的地面上，且强度图上没有油漆脊线，就不推断；车辆开过、与有线车位重叠、或大部分落在未观测区域（墙后）的推断车位去掉。**组装**：柱面作为虚拟隔线；背靠背两排按隔线端点的 10 / 90% 分位判断后对半拆分；排的入口线 / 后端线取各隔线可靠端点的中位数，看不到的一端按实测车位深度补齐；入口朝向行驶过的车道；记录采集时是否有车 | `slots.json/.geojson` |
| objects | **停放车辆**在聚合地图上判定：多视角拼完整、按车位拆分与补全，跨趟变化的车只归属对应那一趟。**移动目标**：逐关键帧检测、匈牙利匹配跟踪、轨迹拼接、轨迹级平滑与尺寸估计 | `objects/static.json`、`moving.json`、`tracks.json` |
| objects2d | 几何叫不出名字的物体：开放词表检测（`models.owlv2`）→ SAM 2 框提示掩膜（`models.sam2`）→ 逐帧类别图（分数高的检测在上）→ 多视角投票到静态地图点（C++ `LabelLifter`）。几何校验：掩膜超过图像面积上限的丢弃，抬到 3D 后要落在该类的离地高度带里（减速带贴地、灯在 1.8 m 以上）。只覆盖规则路线标成结构类或未标注的点，不覆盖标线和规则检出的车辆；车、柱、人行横道、行人、栏杆等提示词只用来抢框，检测结果丢弃 | `objects2d/`（`points.npz`、`detections.json`、`preview.jpg`、`summary.json`） |
| occupancy | 每帧自车坐标系语义占据（静态标签 + 本帧目标框），LiDAR / 相机可见性掩膜 | `occupancy/<trip>/<ns>.npz` |
| frames | 每张图（每一行按曝光时刻取位姿）：静态地图 + 目标框的 z-buffer → 语义标签图；车位角点 / 入口线、标线、目标框投影并做遮挡判断；投影一致性分（投影的标线边缘是否落在图像边缘上）；记录 `pose_set_id` | `frames/<trip>/<cam>/<ns>.json` + `_label.png` |
| features | 语言路线第一步：每张图像的类别无关掩膜（Segmenter2D：SAM 2 / SAM 3）和每个掩膜的语言嵌入（LanguageEncoder：SigLIP 2 / CLIP） | `features/<trip>/<cam>/<ns>.npz` |
| identities | 掩膜经位姿集合和静态地图投到 3D（C++ `IdentityAssociator`）：加入已有身份、合并同一物体的碎片、同一帧不同掩膜互斥；每个地图载体点得到身份 | `identities.npz` |
| language | 每个身份的嵌入 = 各视角掩膜嵌入的加权平均（近、未被图像边界截断的视角权重高），与分类表中每类的中英文提示词比较得到类别；地图点继承身份的类别；再把 3D 标签渲染回每张图，与该图自己的 2D 预测比较，得到跨视角一致率 | `language/labels.npz`、`summary.json` |
| numbers | 车位号 / 分区号：OCR（`models.ocr`）读出的每段文字，按其像素中心的射线落到各层地面，归给附近的车位投票；每排再按"同排编号连续"修正；"C-105"拆成分区 C 和编号 105 | `numbers.json`（`slots()` 读取时合并，重跑 slots 不会丢） |
| rules | 车位尺寸、编号重复、入口远离车道、推断车位、柱补全等进入人工审核队列 | `issues.json` |
| nav | 导航地图，见第 6 节 | `nav/` |
| export | LAS 1.4（类别码 64+id，附楼层 / 动态标志）、PLY、GeoJSON、Lanelet2（parking_space / parking_lot，带车位号 `ref` 和分区 `zone`） | `export/` |

几何规则路线不依赖深度学习，仍是默认产出。

**模型接入点**
- **基础模型接口**（`models/interfaces.py`）：Segmenter2D、LanguageEncoder、DenseFeatures、Matcher、DepthPrior、OcrReader。
- **合成真值实现**（`models/oracle.py`）：从真值渲染派生，可设置类别混淆、嵌入噪声、过分割、像素噪声，用来在没有 GPU 和模型权重时验证整条链路。
- **其他接入点**：
  - `semantics/adapters.py`：真实模型适配器占位、3D 检测器；
  - `recon/stereo.py`：学习式双目；
  - `semantics/markings.py:MarkingSegmenter`。

### 5.2 三路分工与语言路线

| 路 | 组件 | 负责 |
|---|---|---|
| 2D 基础模型 | SAM 2 多粒度掩膜；SigLIP 2（或 CLIP）掩膜嵌入；OCR；DINO 稠密特征 | 认出"是什么"，读出文字 |
| 3D 表示 | 身份级语言特征（现在载体是 LiDAR 点）→ ILGS 式语言高斯（几何冻结，只训练语义属性）→ 蒸馏到点云网络 | 跨视角一致、实例身份；补相机看得少的区域 |
| 几何规则 | 车位排列、柱网、标线平行 / 垂直、编号连续；类别的几何合理性（如挡轮器贴地且低于 0.2 m、标志牌高于 1.8 m） | 约束和校验，不单独判类 |

语言模型推荐 SigLIP 2：
- 多语言，中文提示词可直接用；
- 定位和稠密特征比 CLIP 好；
- Apache 2.0。

**真实模型的接入**（2026-10-22 起，阶段 D）
- **适配器**：`models/sam.py`、`models/siglip.py`、`models/ocr.py`，`models.sam2` / `models.siglip` / `models.ocr` 配置后启用，默认关闭。三者都是 Apache 2.0。

  | 适配器 | 模型 | 做法 |
  |---|---|---|
  | `Sam2Segmenter` | SAM 2.1 Hiera-L | 自动掩膜按面积从大到小绘制成一张掩膜编号图，小物体留在上层 |
  | `Siglip2Encoder` | SigLIP 2 so400m/14-384 | 掩膜外接框加边距裁出，掩膜外置灰（LangSplat 做法） |
  | `RapidOcrReader` | PP-OCR（ONNX） | 中英文和车位号 |

- **FusionPortableV2 地下车库上的第一次试验**（真实车库图像 1024×768）：
  - **SAM 2**：分割质量好。墙、地面、柱、车、人、顶板、管线、斑马线都是干净的区域，每张 19–35 个掩膜，覆盖 63–92%。但每张 5–9 s（主机负载很高），约 1000 张要 2 小时。
  - **SigLIP 2 零样本分类**：
    - 能认出车、人、柱、灯；
    - 但整块地面被判成车道线，斑马线判成梁，红色消防设施判成挡轮器；
    - 以几何标签（LiDAR 地图渲染的逐帧标签）为参照，138 个掩膜里只有 12% 一致：柱 70%，墙 10%，地面 9%，管线 5%，顶板 0%；
    - 加"underground parking garage"模板也没有改善（10%）；
    - 裁出的大块墙面、地面区域，对 SigLIP 只是一块纹理。
  - **相似度量纲**：SigLIP 的最佳类别余弦中位 0.09。`language.min_score` 默认 0.3 是按合成真值编码器定的，用 SigLIP 时会拒掉全部掩膜，要重新标定。
  - **OCR**：抽查的 4 张图里没有读出文字，包括柱上的标志牌。
  - **几何标签转移到 SAM 掩膜**：逐帧标签覆盖率从 42% 只升到 48%。
- **结论与下一步**：
  - 结构类（地面、墙、顶板、柱、梁）继续由几何规则路线定，SigLIP 不参与；
  - 2D 模型只负责几何叫不出名字的物体：标志牌、灯、道闸、挡轮器、行人、两轮车、消防设施；
  - 这类物体要换成开放词表检测（如 OWLv2，Apache 2.0）+ SAM 框提示，而不是给整图掩膜零样本分类；
  - 评估需要一小批人工标注的真实车库图像。
- **开放词表检测试验**（OWLv2-Large，Apache 2.0；FusionPortableV2 地下车库 6 张；阈值 0.2，NMS 0.5）：
  - **速度**：每张 0.05 s，比 SAM 2 自动掩膜快约 100 倍；
  - **认对**：行人、几乎所有顶灯、停放车辆、柱、悬挂的指示牌、红色消火栓箱和灭火器、绿色安全出口灯；
  - **认错**：斑马线被当成减速带（0.23–0.39，提示词里没有"人行横道"来吸收它），楼梯栏杆当成道闸；墙上的大幅彩绘箭头和大号指示牌没有作为标志牌检出；
  - **漏检率**：没有人工标注无法给出；
  - **结论**：物体由"检测框 → SAM 2 框提示得到掩膜"产生，比给整图自动掩膜零样本分类合适。
- **`objects2d` 阶段在 FusionPortableV2 地下车库全段上**（每个相机每 4 张取 1 张，共 922 张，224 s，每张约 0.24 s，含 SAM 2 掩膜和 3D 投票）：
  - 检测 14584 个；117142 个地图点被改标（地图共 934 万点）；
  - 加几何校验前后对比（置信的地图点数）：

    | 类别 | 不校验 | 加面积上限、离地高度带和更多抢框提示词 |
    |---|---|---|
    | 灯 | 39532 | 39461 |
    | 标志牌 | 51495 | 45072 |
    | 减速带 | 45295 | 10504 |
    | 道闸 | 27668 | 5656 |
    | 其他（消防设施、锥桶） | 20790 | 17300 |
    | 行人（静态地图上） | 18088 | 0 |

  - **去掉的错误**：
    - 一个框盖住明亮的地面条带，SAM 掩膜变成整片地面，被当成减速带；
    - 坡道护栏被当成道闸；
    - 行人本属移动目标，交给 objects4d。
  - **俯视图**：灯在走廊上排成整齐的纵向直线，标志牌沿墙分布，有横跨走廊的减速带条。没有人工标注，准确率还给不出。
- **OCR**（FusionPortableV2，含标志牌的 49 张图）：
  - **整图 OCR** 读出 101 段：EXIT ×10、5A ×9、中央区 ×7、2号门出口、南区、Central、更多车位。正是导航要的分区和出口信息。
  - **标志牌框裁出放大 3 倍再读**：不同的文字只有 24 段，部分读乱（如"5As粒脑->"），对远处的小标志牌有帮助，与整图 OCR 互补。
  - **车位号**：这座车库的样本里没有出现车位号。
  - **下一步**：把文字挂到抬到 3D 的标志牌上，作为导航的分区和出口地标。

**ILGS 要点**（Identity-aware Language Gaussian Splatting，ICCV 2025）
- **表示**：每个高斯在 3DGS 属性之外，再加 3 维语言嵌入（CLIP 特征经自编码器压缩，沿用 LangSplat）和 16 维身份嵌入。
- **训练目标**：
  - RGB：L1 + D-SSIM；
  - 语言特征图：对 CLIP 特征图的 L1；
  - 身份特征图：对多视角一致身份标签的交叉熵；
  - 身份感知一致性：同一身份的语言嵌入拉近，不同身份推远；
  - 几何与语义端到端联合训练。
- **推理**（渐进掩膜扩展）：按身份分段，从与文本最相似的种子段开始，逐步并入与种子相似度相差不到 10% 的相邻段。
- **结果**：LERF-mask 平均 mIoU 80.5（LangSplat 57.6，Gaussian Grouping 72.8）。
- **局限**：
  - 论文场景是桌面尺度，位姿来自 SfM；
  - 身份标签由视频跟踪器 DEVA 生成，复杂场景里会出错；
  - 只处理静态场景；
  - 代码基于非商用的 Inria 光栅器。

**车库尺度的三处改造**
1. **身份用几何关联，不用视频跟踪**（已实现）：
   - 原因：几千帧、结构重复的车库里，跟踪器会断链或串号。
   - 做法：每帧掩膜按共享位姿和 LiDAR 深度投到 3D，加入或合并身份，同一帧的不同掩膜互斥。
   - 必须用地图法向剔除背面，否则楼板上下两面（上层地面与下层顶板）会合成一个身份：剔除后身份纯度从 0.79 升到 0.90。
   - 车窗、反光地面这类几何不可靠的地方，计划用掩膜的 DINO 特征相似度补充。
2. **语言特征按身份存全维**（已实现）：
   - 原因：3 维自编码器压缩会损失开放词汇能力。
   - 做法：每个身份存一个全维嵌入，即多视角加权平均；高斯（或点）只存身份。
   - 地面、顶板、墙这类背景类，计划保留逐高斯的低维语言场。
3. **几何冻结**（待 3DGS）：只优化语义属性，语义损失不能把高斯从 LiDAR 锚定的位置拉走。

先按论文原样实现一版（3 维语言 + 16 维身份）作为基线，再与改造版对比。身份关联、身份级特征、渐进扩展都不依赖高斯：量产用高斯，没有 GPU 的环境用 LiDAR 点作载体。

**查询与输出**
- **提示词与阈值**：每个类别写一组中英文提示词；SigLIP 的 sigmoid 分数用少量人工标注帧逐类标定阈值。
- **长尾目标**：消防栓箱、充电桩、施工围挡等用开放词汇查询，审核后并入分类表。
- **文字**：车位号、分区号不靠 CLIP / SigLIP，靠 OCR 加"同排编号连续"修正（`numbers` 阶段）。
- **移动目标**：移动目标和跨趟变化的车辆不进共享的语言场，由 4D 框负责；类别用各帧掩膜投票。
- **地面要素**：标线、车位线和地面文字计划在 3DGS 正射影像上做分割、语言查询和 OCR（俯视、无畸变、公制尺度），再回投原始帧核对。
- **逐帧标签**：现在由点云 z-buffer 渲染；有了语言高斯后改为直接渲染每台相机每一帧的语义图和实例图（3DGUT 直接渲染鱼眼），遮挡由渲染深度决定。
- **跨视角一致率**：渲染出的标签与该帧 2D 模型结果的一致程度；冲突区域进入人工审核。
- **点云网络**：如 Point Transformer V3，用审核过的 3D 标签训练，补全相机覆盖少的区域（如车顶），也作为新车库的第二意见。

## 6. 导航地图（`nav` 阶段）

把语义结果整理成导航能直接用的地图：
- 按地址找车位，例如"去 B2 C 区 105 号车位"；
- 给出停车目标位姿；
- 规划不穿墙的全局路径。

几何算法在 C++（`nav_map`）：距离变换、骨架、路网提取、最短路、栅格 A*。编排在 `python/garage_recon/nav/`。

**分层（每层 0.1 m 栅格）**
- **障碍按几何判定，不只看类别**：离地 0.12 m 到车高 + 0.2 m 之间的静态点都算障碍，墙被错分成别的类也照样挡住。
  - 无类别的点每格累计观测至少 6 次才算障碍。移动目标的残留点、噪声通常只被观测一两次，不过滤会在车道里形成假障碍。
- **类别只用于分层**：
  - 固定结构：墙、柱、护栏、未分类物体；
  - 悬挂结构：管线、梁、标志，低于车高时才算；
  - 采集时的停放车辆；
  - 可越过的低矮物：减速带、挡轮器。
- **可行驶区** = 观测到的地面 + 车辆开过的区域 − 障碍。
  - 四周都已观测、面积小于 20 m² 的未观测地面按地面处理（被车挡住或线束间隙）；
  - 大片未知区域仍算障碍。
- **输出**：
  - ROS map_server / nav2 的 `level_<k>.pgm/.yaml`，固定障碍为占据；
  - 各层所有图层 `level_<k>_layers.npz`；
  - 彩色预览图。

**路网**
- **车道中线**：每层取车道区（可行驶、非车位、非坡道）中与障碍保持"半车宽 + 0.3 m"间距的部分，细化成骨架，再提取节点和边。路网上每一点都留有这个间距，沿路网的路线不会穿墙、擦柱。
- **桥**：误检的车位或个别窄点会把骨架截断。同一层断开的几块用栅格 A* 补"桥"：可以穿过车位，只要求车身半宽。
  - 桥在 QA 里列出，供复核；
  - 真正过不去的窄点保持断开。
- **坡道**：每条坡道生成一条从坡顶到坡底的边，两端用直连线接到上下两层的路网，直连线经过障碍层检查。

**车位目标点（`goals.json`）**
- **停车位姿**：车位中心，车头进与倒车进两个朝向。
- **接近点**：从车位入口沿车道方向找到的车道中线点，带车道朝向。
- **入口节点**：入口外 0.3 m 的车位节点，经直连线接入路网。直连线只检查墙、柱等固定障碍，不看采集时的停车（占用会变）。
- **可达性**：从入口出发的路线长度，以及是否可达。入口默认取第一趟的起点（楼层取离它最近的地面），可用 `nav.origin` 配置。

**地址**（`nav/address.py`）
- **组成**：
  - 楼层名：`nav.level_names`，例如 `[B1, B2]`；
  - 分区：来自 OCR，或配置的分区多边形 `nav.zones`；
  - 车位号：来自 OCR。
- **查询写法**："B2 C区 105号""b2-c-105""负二层C区105""C105"，或车位编号。
- 没有车位号时，地址退回车位编号。

**QA（`qa.json`）**：从入口到每个车位都按路网规划，并逐段检查：
- 碰到固定障碍的路线数（应为 0）；
- 路线上的最小间距；
- 不可达车位：用栅格 A* 复核，分为"路网断开"和"地图上本来就过不去"；
- 桥；
- 开过的车位、车位内的障碍；
- 采集轨迹落在路网上的比例。

## 7. 测量级：定义与验收

### 7.1 来源标记与门槛

每个 3D 元素带来源标记和不确定度：

| 标记 | 来源 | 用途 | 现状 |
|---|---|---|---|
| L | LiDAR 实测，多次观测融合 | 测量级，进入矢量测量 | 已实现（测量点云每点带 σ） |
| G | 3DGS 几何，经留出的 LiDAR 扫描或多视角一致性验证 | 测量级，σ 按核验结果给出 | 待 3DGS |
| P | 仅有先验（DA3，或未通过核验的 3DGS） | 只用于可视化和完整度，不进入矢量测量 | 待 DA3 / 3DGS |

门槛为初定值，需在手持真值车库上标定（`acceptance.thresholds`）：

| 类别 | 指标 | 初定门槛 |
|---|---|---|
| 骨架 | 检查点 RMSE / CE90（手持真值）、多趟重复性、平面厚度 | 检查点 RMSE ≤ 2 cm |
| 表面 | 地图到真值表面的距离，按 L / G / P 分开 | p95 ≤ 3 cm |
| 完整度 | 车辆观测到的真值点被地图复现的比例 | ≥ 90% |
| 矢量 | 车位角点、标线、柱中心的检查点误差；编号正确率 | 角点 RMS ≤ 2 cm |
| 3DGS 外观 | 留出帧的 PSNR / SSIM / LPIPS | 用于正射影像质量把关 |
| 语义 | 3D mIoU / mBIoU、逐帧 mIoU、实例 AP、跨视角一致率 | 按类别设定 |

### 7.2 手持真值验收（`accept`）

把车载重建配准到手持真值的坐标系，再按门槛出报告。

手持真值目录（扫描仪导出 + 在其上的标注）：

```
handheld/cloud.(ply|las|laz|pcd|xyz|txt|csv|npz)   手持点云，自身坐标系，重力对齐（z 向上）
handheld/features.json   可选：在手持点云上数字化的 levels / columns / slots / lines
handheld/points.csv      可选：测量的点（全站仪靶标等）：id, role(control|check), x, y, z[, map_x, map_y, map_z]
```

流程：
1. **配准**：粗配准（C++ `align_gravity_aligned`）+ 多尺度点到面 ICP（地图结构点 → 手持点云），然后二选一：
   - `control`（默认）：按测量惯例，只用控制点定坐标系。
     - 有 `points.csv` 里带地图坐标的控制点时用它们；
     - 没有时，每层取柱网四角的 4 根柱作控制点，在地图上量测柱心后做刚体拟合，其余柱作检查点。
   - `auto`：直接用 ICP 结果，即整张地图的最佳刚体拟合。
2. **检查点**：每根柱在地图点上量测（四个柱面的点定柱心 x / y，柱周地面定高程），与手持标注比较：
   - 3D / 平面 / 高程 RMSE、CE90、LE90；
   - 平均误差向量（系统偏差）；
   - 分层统计。
3. **表面精度**：地图结构点到手持表面（局部平面）的距离。
   - 统计中位、p90、p95、2 cm 内比例，分层、按来源标记；
   - 水平面的有符号偏差即高程偏差；
   - 点带 σ 时，统计误差落在 1σ / 2σ 内的比例（检验 σ 是否可信）。
4. **完整度**：车辆观测到的手持点（0.5 m 内有地图点）中，有多少被地图在 5 cm 内复现。
5. **矢量**：车位角点（按 IoU 匹配）、语义检测的柱心、标线中心线，都在手持坐标系里比较。
6. **结论**：按 7.1 的门槛判定。

输出：
- `work/acceptance/report.json`；
- `report.md`（中文报告）；
- 每层的偏差图 `deviation_level_<i>.png`。

真实项目只需把手持结果放成上面的目录，其余不变。标注可由人工在手持点云上数字化。

合成数据的手持真值（`data/synthetic/handheld.py`）：
- **扫描**：沿车辆路线每 2 m 一个扫描位置，1.5 m 高的近球形扫描（0.5° × 1°），3 mm 测距噪声，4 cm 体素平均。
- **场景差异**：另一批停放车辆，相当于不同时间采集。
- **SLAM 误差**：万分之一比例误差，每层 2 mm 高程漂移。
- **坐标系**：相对世界系旋转 23.7°，平移约 160 m。真实变换只写在 `gt/handheld.json`，验收工具不用它。

## 8. 3DGS、DA3 与 DINO

### 8.1 分工

| 组件 | 负责 | 不负责 |
|---|---|---|
| LiDAR + IMU + 轮速 | 位姿、绝对尺度、主体表面（墙、柱、地面、顶板） | 纹理；LiDAR 没测到的区域 |
| DA3（及双目） | LiDAR 空洞处的稠密深度先验；3DGS 的初始化和正则 | 位姿、尺度、最终几何 |
| 3DGS | 细节（管线、喷淋、细杆、标志牌、边缘）、外观、正射影像、任意视角的深度 / 法向 / 标签渲染 | 改动 LiDAR 已测的表面 |
| DINO | 跨视角、跨趟的对应关系 | 直接输出位姿 |

LiDAR 空洞指累积地图之后仍然没测到或采样很稀的地方：
- 线束间隙、车与车之间；
- 细杆和管线、标志牌边缘；
- 背向车道的柱面、顶板上的设备。

规划中的阶段：
- **重建**：map 之后加 depth_prior（DA3）→ gs（分块训练）→ gs_verify → ortho；
- **语义**：加 lang_field（语言高斯训练）→ query（类别与实例）。

### 8.2 DA3

- **位姿条件模式**：
  - 把同一套位姿（world→camera）和内参传给 DA3，并设 `align_to_input_ext_scale=True`，输出深度就按我们的位姿定尺度。
  - DA3 自己估计的位姿只做诊断：与我们的位姿差别大，说明标定或同步有问题。
- **输入**：
  - 鱼眼图先切成几张虚拟针孔视图，因为 DA3 只接收针孔内参；双目两路一起输入。
  - 默认处理分辨率是长边 504 像素，所以 DA3 深度只是低分辨率先验，细节靠 3DGS 在原始分辨率上训练。
- **与 LiDAR 对齐（C++ `FuseDepthPrior`）**：每帧拟合 l = s·p + b，在相对残差上做 Cauchy 加权的迭代重加权最小二乘。
  - **拟合用的点**：拟合点是该帧可见的 LiDAR 地图点，按亚像素位置取先验深度，不用 z-buffer 图像。掠射的地面上一个像素覆盖很长一段距离，z-buffer 取最近点，会偏短 1–3%。
  - **剔除**：残差中位数超过 10% 的帧丢弃。按 24 px 网格逐格检查，残差超过 15% 的格子连同四邻丢弃（细杆前后、反光、天空）。
  - **输出**：每个像素的距离、置信度和来源（LiDAR / 先验 / 无）。先验只填 LiDAR 空洞，即离任何 LiDAR 像素超过 4 px 的地方；空洞里的先验点另存一份，作为 3DGS 的初始化（来源 P）。
- **实现**：
  - `depth_prior` 阶段，`models.backend: real` 加载 `models/da3.py`；
  - 鱼眼按偏航 ±28°、80° 视场切成两张虚拟针孔图（504×378），深度再按射线距离映射回鱼眼；
  - 每次送 16 个时刻的全部相机，GPU 推理与 CPU 融合流水并行；
  - DA3 自己估计的位姿经相似变换对齐到我们的位姿，作为诊断记入 `frames.csv`。
- **Keble-02 实测**（DA3-BASE，3 路鱼眼共 1800 张，288 s）：
  - 拟合后残差中位 3.9%，93% 的帧有效；
  - DA3 对位姿条件给出的尺度大多准确（中位 0.96），但 10% 的帧偏离 30% 以上，所以逐帧拟合不能省；
  - DA3 自估位姿与我们的位姿差中位 1.4°、0.36 m；
  - 加上俯仰 ±18° 的视图后变差（残差 4.6%）：天空 / 地面为主的视图 DA3 拟合不好。
- **模型选择**：
  - 可商用：DA3-BASE / DA3-SMALL（任意视角，支持位姿条件）、DA3METRIC-LARGE、DA3MONO-LARGE，均为 Apache 2.0。
  - 只用于研究对照：DA3-GIANT / LARGE / NESTED 及前馈 3DGS 输出，CC BY-NC 4.0。
  - Keble 实测（每 10 张取 1 张，双视图，16 个时刻一批）：

    | 模型（许可） | 有效帧 | 拟合后残差中位 | 拟合前尺度 p10–p90 | DA3 自估位姿与我们的差 | 耗时（180 张） |
    |---|---|---|---|---|---|
    | SMALL（Apache 2.0） | 76% | 5.6% | 0.74–1.67 | 1.2°、0.42 m | 40 s |
    | BASE（Apache 2.0，默认） | 93% | 3.9% | 0.71–1.06 | 1.4°、0.36 m | 38 s |
    | GIANT（CC BY-NC） | 97% | 1.7% | 0.98–1.01 | 0.4°、0.10 m | 49 s |

    GIANT 的深度误差不到 BASE 的一半，尺度也稳得多，只慢约 30%。商用只能用 BASE；需要更好的空洞先验时，要么另找可商用的大模型，要么用 GIANT 蒸馏一个可商用的模型。
- **先验实际填了多少**（DA3-BASE，`depth_prior/frames.csv` 的逐帧均值）：

  | 数据 | 来自先验的像素占比 | 有先验像素的帧 |
  |---|---|---|
  | Keble-02 | 0.1–0.7%（按相机） | 14–76% |
  | Keble 两趟 | 0.2–0.4% | 36–58% |
  | Hilti | 0.01–0.04% | 4–12% |

  - 先验在 3DGS 的深度目标里几乎不起作用。`summary.json` 里的 `prior_fraction` 是逐帧中位数，多数帧没有先验像素，所以接近 0。
  - **空洞在哪**（Keble 18 帧逐项统计）：LiDAR 覆盖 85% 的像素，空洞 14%，几乎全在地平线以上。
    - 约四成在两张虚拟视图之外（鱼眼边缘的天空）；
    - 视图内的空洞大多是天空，DA3 给的置信度中位约 0，按 `min_confidence` 0.05 剔除，这是对的；
    - 真正被填上的是 LiDAR 量程外的远处立面和树冠。
  - **加入远处的上下文帧**（`depth_prior.context_frames`，默认 0 即关闭）：
    - **做法**：每批 16 个连续时刻之外，再加 16 张趟内别处的图，只用来扩大基线，它们的预测丢弃。连续帧单独已经覆盖约 8 s、10 m 的基线，但对 60 m 外的立面仍然太短，DA3 给的置信度很低。
    - **注意**：需要 `models.da3.batch_views` ≥ 2 ×（每批图数 + 上下文帧数），这里是 128，否则上下文帧落在另一次推理里，不起作用。
    - **Keble-02 实测**：DA3-BASE，杆臂修正后的位姿；精度是先验像素反投影到世界后，到 TLS 真值的距离，只统计 TLS 扫到的区域。

    | 配置 | 有效帧 | 每张图的先验像素（前 / 左 / 右） | 先验对 TLS 误差中位（相对） | p90 | 置信度 ≥ 0.3 的先验像素（每 5 张抽 1 张；3DGS 初始化只取这一档） |
    |---|---|---|---|---|---|
    | 只有连续帧（默认） | 92% | 0.16 / 0.69 / 0.08% | 90 cm（1.5%） | 175 cm | 227 个，114 cm |
    | + 16 张，整趟均匀取 | 89% | 0.77 / 3.10 / 0.10% | 81 cm（1.3%） | 169 cm | 8.5 万个，62 cm |
    | + 16 张，离本批 15–40 m（`distance`） | 92% | 0.71 / 2.67 / 0.11% | 80 cm（1.3%） | 163 cm | 5.3 万个，63 cm |

    - **结论**：
      - 先验像素多了约 4 倍，精度不降反升；
      - 先验像素到相机的距离中位约 61 m，误差约为距离的 1.3%；LiDAR 像素对照为 4.4 cm；
      - 按距离选的上下文帧不降低有效帧比例，DA3 耗时只多 7%（313 / 293 s）。
    - **对 3DGS 的影响**（Keble-02，同一份位姿，30k 步）：

      | 先验 | 留出 PSNR / SSIM | 射线深度误差中位，5 cm 内 | 来源 P 的不透明高斯：个数，到 TLS 中位 |
      |---|---|---|---|
      | 只有连续帧 | 25.61 dB / 0.811 | 5.4 cm，47% | 406 个，22.0 cm |
      | + 上下文帧（`distance`） | 25.71 dB / 0.812 | 5.4 cm，47% | 3673 个，12.5 cm |

      - 来源 P 的高斯多了 9 倍，也更准；但它们不到总数（490 万）的 0.1%，留出 PSNR（+0.1 dB）和射线深度都在噪声内。
      - 所以默认保持关闭。需要 LiDAR 量程外的远景时（远处立面、户外正射的边缘）再打开，同时把 `models.da3.batch_views` 设为 128。

### 8.3 3DGS

3DGS 对位姿误差比点云地图敏感得多，误差会直接表现为模糊和重影：
- 相机时间偏差 5 ms、车速 4 m/s，就是 2 cm 错位；
- 0.1° 姿态误差在 10 m 处是 1.7 cm。

因此第 4 节的骨架（IMU 预积分、连续轨迹、BA、相机标定、位姿集合）是 3DGS 的前提。

- **实现**：用 gsplat（Apache 2.0）的 3DGUT 模式，直接在原始鱼眼图上训练，支持卷帘快门，不需要去畸变。不用 Inria 原版光栅器（非商用许可）。
- **相机**：每一行像素的位姿 = 位姿集合在该行曝光时刻的值 ∘ 相机外参。关闭逐帧位姿优化。
- **初始化**：全部 LiDAR 测量点都生成锚定的扁平高斯（C++ `InitGaussians`）。
  - 法向轴取点的 σ；
  - 切向取 0.8 × 局部点距，保证 5 cm 网格至少 99.8% 不透明；
  - DA3 点只补 LiDAR 空洞。
- **损失**：
  - 光度：L1 + D-SSIM，每张图一组曝光 / 白平衡补偿；
  - LiDAR 深度和强度：沿 LiDAR 射线渲染（参考 SplatAD，C++ `GaussianRayRenderer` 已实现评估用版本）；
  - DA3 深度：只用在 LiDAR 空洞，按置信度加权，随训练衰减；
  - 法向：平面区域用 LiDAR 平面法向；
  - 扁平化（最小尺度轴趋零），以及多视角几何一致（参考 PGSR）。
- **骨架约束**：C++ 预先算好 LiDAR 表面距离场、自由空间栅格（`FreeSpaceCarver.free_mask`）和各层地面高度，训练时在 GPU 上查表。
  - 落在 LiDAR 表面附近的高斯受锚定惩罚，偏离超过容差的剪掉；
  - LiDAR 射线穿过的自由空间里不允许有高斯，用来清除漂浮物；
  - 地面以下不允许有高斯，否则环氧地坪的倒影会在地面下长出"镜像"几何。
- **LiDAR 要素的覆盖**：3DGS 不会自动覆盖全部 LiDAR 要素。相机拍不到的地方没有外观监督，标准的不透明度重置和剪枝会把这些高斯删掉。
  - 实测地下车库（手持，前向双目）只有 54% 的 LiDAR 点被相机拍到过：顶板 13%、柱 40%、管线 43%。
  - 有效视角不足 3 个的高斯标为"冻结"：几何和不透明度保持初值，不参与不透明度重置和剪枝，颜色先用反射强度代替，并标为"无外观"。有效视角指曝光正常、未遮挡、未被掩膜。
  - 高斯带 LiDAR 强度通道：标线可以从同一个模型里取，相机看不到的高斯也能由 LiDAR 监督强度。
  - 跨趟变化的物体按趟生成专属高斯，只在本趟的视角里参与渲染；或者在图像中屏蔽。
  - 相机覆盖率按类别进入 QA，作为 3DGS 的验收项（C++ `CameraCoverage`）。同一工具也能在已有轨迹上评估设想中的相机布置，如环视鱼眼、朝上相机。
- **掩膜**（C++ `RenderTrainingMask`）：屏蔽移动目标（动态点 + 4D 框投影）、跨趟变化物体、自车车身、过曝的灯具。
- **分块**：按楼层和坡道分区，约 40 m 一块、带重叠，并行训练。合并时每个高斯归属于它所在块的核心区。
- **核验（C++）**：
  - 渲染深度对留出的约 10% LiDAR 扫描的误差；
  - 高斯表面到 LiDAR 地图的距离分布，按区域出偏差图；
  - 对手持真值按 L / G / P 分开统计。
- **产出**：
  - 3DGS 模型；
  - 表面网格（渲染深度做 TSDF 融合）；
  - 每层的正射影像，替代现在的 5 cm 地面栅格和地面纹理；
  - 每台相机任意时刻的深度和法向渲染，逐帧标签的遮挡判断改用它。
- **采集要求**（写进采集规范）：
  - 曝光时间上限：4 m/s、20 ms 曝光就有 8 cm 运动模糊；也可以用连续轨迹在曝光窗内取多个位姿渲染，为模糊建模。
  - 增益上限、防频闪。

**实现**（`recon/gs.py`、`recon/gs_verify.py`，`gs.enabled`）

- **外观学不出来的原因是曝光，不是流程**：
  - 训练图本身也只有 17.4 dB，说明是拟合不了，而不是过拟合；
  - 露天楼面在阳光下，各路相机每张图中位有 20–43% 的像素饱和（≥ 250），饱和的是被照亮的地面和结构，不只是天空（Keble 前视主要是天空 17%，右视只有 2%）；
  - 训练掩膜去掉了饱和像素，剩下的监督太少；单色图像的信息量也更少；
  - 相机投影已用 LiDAR 叠加图核对过，是对齐的（9.7）；
  - RoMa 标定（每 8 张取 1 张）：五路相机标定前重投影 RMS 已在 1.2–1.4 px（cam2 为 2.45 px，标定后 1.9 px），时间偏差 0.7–2.5 ms，步行速度下只是毫米级。所以问题也不在相机标定。
- **试过：饱和像素作单边监督**（`gs.saturated_weight`，默认 0 即关闭）：
  - 饱和像素只说明"至少这么亮"，所以只在渲染比饱和值暗时罚（最亮通道）；
  - 留出图另统计饱和像素渲染得够亮（不低于饱和值 0.05）的比例。

  | 杆臂修正后的位姿 | 留出 PSNR / SSIM（非饱和像素） | 训练图 PSNR | 留出饱和像素渲染够亮 | 射线深度误差中位，5 cm 内 |
  |---|---|---|---|---|
  | 不加 | 16.74 / 0.714 | 17.60 | 3.7% | 6.3 cm，45% |
  | 权重 0.5（增益 / 偏置也跟着调） | 15.01 / 0.696 | 15.71 | 85.4% | 7.0 cm，43% |
  | 权重 0.5，只经过高斯（`gs.saturated_fixed_appearance`） | 15.55 / 0.697 | 16.16 | 79.0% | 7.7 cm，41% |
  | 权重 0.1，只经过高斯 | 16.41 / 0.708 | 17.24 | 48.3% | 6.9 cm，43% |

  - **增益 / 偏置能跟着调时**：饱和区确实亮了，但其余像素掉 1.7 dB。最省事的办法是把整张图的增益调高，其余像素就一起变亮了。
  - **只经过高斯时**：损失小一些（同样权重 0.5，15.01 → 15.55 dB），但仍是取舍：饱和区越亮，其余像素越差，射线深度也变差。
  - **结论**：
    - 默认关闭；
    - 不加时，阳光照亮的地面渲染成暗灰（只有 3.7% 够亮）；
    - 正射影像要求"看起来对"时，可以用权重约 0.1 换一半饱和区变亮，代价是留出 PSNR 低 0.3 dB。
- **结论**：几何仍然锚在 LiDAR 上，但这份数据不适合评估外观。这正是"采集要求"里规定曝光上限的原因。

**留出 LiDAR 射线上的深度偏短**：渲染深度比实测距离短，这是核验暴露出的主要问题。

- **原因一：表面噪声**。
  - 不透明的扁平圆片铺在有噪声的点层上，射线停在噪声层的最前面。
  - 合成平面实验：1.5 cm 的法向噪声就会偏短 2–5 cm。
  - Keble 地图多数表面厚 2–5 cm，未训练的初始高斯就已偏短 8.6 cm。
  - 修法：锚点先投影到半径 15 cm 的局部平面上（一步 MLS，C++ `ProjectToLocalPlanes`），未训练时降到 −2.7 cm。
- **原因二：深度目标本身偏短**。
  - z-buffer 取每个像素里最近的点，渲染出的 LiDAR 深度偏短。
  - 改用第一表面平均深度（C++ `RenderSurfaceDepth`），深度先验阶段存储的 LiDAR 深度也用它。
- **原因三：训练又把表面往相机拉**。Keble 上跑 10k 步的对照：

  | 配置 | 留出 PSNR | 射线深度误差中位 | 5 cm 内 |
  |---|---|---|---|
  | 深度权重 0.1 | 24.5 dB | 6.8 cm | 39% |
  | 深度权重 1.0（新默认） | 24.2 dB | 5.4 cm | 47% |
  | 尺度最多增长 1.5 倍 | 22.7 dB | 5.3 cm | 48% |
  | 三项都加（另加不加密） | 22.5 dB | 4.9 cm | 51% |

  - 训练越久偏差越大：权重 0.1 时，10k 步 6.8 cm，30k 步 8.0 cm。
  - 限制尺度增长对几何有效，但 PSNR 掉 1.8 dB，因为圆片要靠变大才能盖住点与点之间的空隙。
  - 结论：保留 LiDAR 几何靠深度损失；做测量级应用时，几何以 LiDAR 地图为准，3DGS 只补外观和空洞。
- **对策试验：从 LiDAR 视角监督深度**（`gs.lidar_views`，默认关闭）：
  - **做法**：在每个关键帧的 LiDAR 原点放 4 个重力对齐的针孔视图（各 90° × 110°，256 px 宽），渲染静态地图的第一表面深度作目标，与相机图像的深度目标同法（`RenderSurfaceDepth`）；每 2 步取一个关键帧的 4 个视图，一次 gsplat 调用渲染；罚相对深度误差，以及 LiDAR 看到表面处的不透明度不足。
  - **为什么留出评测仍公平**：留出射线来自非关键帧扫描，这项损失只用关键帧。
  - **Keble-02 实测**（杆臂修正后的位姿，30k 步；"地图圆片"一行是同一批 39.6 万条留出射线上，未训练的初始高斯，可看作这项指标的实际下限）：

    | 配置 | 留出 PSNR / SSIM | 射线误差中位 | 5 cm 内 | p90 | 射线未击中 | 加密出的高斯（来源 G）到 TLS 中位，5 cm 内 |
    |---|---|---|---|---|---|---|
    | 未训练的地图圆片（下限参考） | – | 4.05 cm（有符号 −2.66） | 57% | 28 cm | 0.5% | – |
    | 训练，不加（默认） | 25.61 dB / 0.811 | 5.41 cm | 47% | 29 cm | 0.6% | 10.1 cm，30% |
    | 训练，LiDAR 视角权重 1.0 | 25.57 dB / 0.809 | 5.27 cm | 48% | 29 cm | 0.1% | 7.4 cm，35% |
    | 训练，LiDAR 视角权重 0.3 | 25.62 dB / 0.810 | 5.37 cm | 48% | 29 cm | 0.0% | 8.0 cm，29% |

  - **结论**：
    - 留出 PSNR 不变；
    - 射线几乎不再穿空；
    - 加密出的高斯更贴近真实表面（10.1 → 7.4 cm）；
    - 但射线误差中位只从 5.41 降到 5.27 cm。训练比未训练的地图圆片差约 1.4 cm，这项损失只挽回了约 0.14 cm。
  - **p90 约 29 cm 在下限里也有**，来自射线和地图本身（边缘、植被），不是训练造成的。
  - **未训练的圆片也偏短 2.7 cm**：偏短有一部分在表示方式（圆片第一表面），不全在训练。
  - **Hilti 实测**（杆臂修正后的位姿；不加的一行是同一版代码重跑的对照）：

    | 配置 | 留出 PSNR / SSIM | 射线误差中位 | 5 cm 内 | p90 | 射线未击中 |
    |---|---|---|---|---|---|
    | 不加 | 16.74 dB / 0.714 | 6.27 cm | 45.5% | 2.76 m | 0.05% |
    | LiDAR 视角权重 1.0 | 16.81 dB / 0.713 | 5.90 cm | 46.7% | 2.52 m | 0.006% |

  - **两份数据结论一致**：
    - 几何变好，Hilti 更明显（中位 −0.4 cm，p90 −24 cm）；
    - 外观不变；
    - 训练时间约 1.4 倍（每 2 步多一次 4 视图渲染，3DGUT 的开销主要在逐高斯投影，与像素数关系不大）。
  - **默认仍关闭**：测量级几何以 LiDAR 地图为准，3DGS 的几何收益抵不上训练时间。需要用 3DGS 的深度时（逐帧深度 / 法向渲染、空洞处的几何），打开 `gs.lidar_views.enabled`。
- **户外的天空**：天空里会长出高斯（户外特有，车库没有天空）。可学习的背景色只能部分压住。
  - **试过的简单掩膜**（`gs.sky_weight`，默认 0 即关闭）：把"高于地平线 5° 且没有 LiDAR / 先验深度"的像素当作天空，惩罚其不透明度（权重 0.1）。

    | 数据 | 留出 PSNR（不加 → 加） | 留出 LiDAR 射线未击中 |
    |---|---|---|
    | Keble-02 | 24.0 → 21.6 dB | 0.3% → 8.2% |
    | Keble 两趟 | 24.2 → 22.3 dB | 0.3% → 6.2% |
    | Hilti | 16.4 → 15.6 dB | 0.0% → 1.4% |

  - **为什么更差**：超出 LiDAR 量程的立面、树冠和深度图的空洞都满足这个条件，真实表面被压成透明，射线也就穿过去了。
  - **改用语义天空**（`gs.sky_source: segmentation`）：
    - 天空 = DINOv2 + Meta 的 ADE20K 线性头（Apache 2.0）判为天空，且没有 LiDAR / 先验深度；去掉小块；
    - 惩罚按每张图的像素数归一，与光度损失一致。

    | Keble-02（权重 0.5） | 留出 PSNR | 去掉天空像素的留出 PSNR | 训练图 PSNR | 射线未击中 |
    |---|---|---|---|---|
    | 不加 | 25.58 dB | 26.54 dB | 26.07 dB | 0.61% |
    | 加 | 24.20 dB | 25.23 dB | 24.59 dB | 0.15% |

    - 掩膜覆盖 12% 的像素，形状合理，但非天空部分也掉 1.3 dB：横跨天空边界的大高斯、被判成天空的过曝楼顶被压成透明，并影响其他视角。
    - **第一版的两个错误**（已修正）：一是掩膜排除了饱和像素，只覆盖 0.9%；二是惩罚只在这些像素上求平均，每个像素的权重是光度损失的约 1 万倍。
  - **结论**：天空损失默认关闭，不再继续。车库里没有天空，这是户外数据特有的问题。
- **图像目标放在 GPU 上**（`gs.images_on_gpu`，默认开）：
  - 紧凑格式（uint8 / float16 / bool）在建好覆盖度后一次搬上 GPU；
  - Keble 每个训练进程的主机内存约 8 GB，主机内存（容器上限约 110 GB）不再限制并行训练的数量；
  - 结果与放在主机上相同（Keble-02 留出 23.97 / 24.00 dB）。

### 8.4 DINO：几何对应

| 用途 | 做法 | 现状 |
|---|---|---|
| 相机标定与时间同步 | 稠密匹配做粗对应，再细化到亚像素（RoMa 式：DINOv2 粗匹配 + 卷积特征细化）；结合 LiDAR 深度构造重投影残差 | **已接入 RoMa**（`models.roma`，`models/dino.py` 的 `RomaMatcher`），见下 |
| 回环与多趟对齐 | DINO 全局描述子（AnyLoc 式聚合）给出外观候选，与 Scan Context、OCR 车位号一起排序，仍由 ICP + PCM 判定 | **已实现**（`loops.appearance`，C++ `VerifyAppearanceLoops`），见下；OCR 候选未做 |
| 语义身份关联 | 掩膜级 DINO 特征相似度，补充 3D 重叠关联 | 特征已接入（`Dinov2Features`，`models.dino`）；掩膜要等 SAM 适配器 |
| 手持真值配准 | 手持设备带相机时，用 DINO 匹配给初值，再 ICP | 现在用几何粗配准 |
| 跨趟变化（可选） | 3DGS 渲染图与新一趟图像的 DINO 特征差 | 待 3DGS |

- **精度**：DINO 的 patch 步长是 14 或 16 像素，只够做粗对应；用作几何约束之前必须细化到亚像素。
- **复用 DA3 特征**：DA3 的编码器本身是 DINO 结构，可以评估直接复用它的中间特征（`feat_layer`），省一次 DINO 推理。

**实现**
- `models.backend: real` 时按配置加载 `models.roma` 和 `models.dino`。模型在第一次使用时才加载，只跑 3DGS 的阶段不会占着 RoMa 的显存。
- **RoMa**：
  - 用 outdoor 权重，局部相关用 PyTorch 实现（`use_custom_corr=False`，不需要额外的 CUDA 扩展）；
  - 有查询点时在稠密 warp 上按亚像素采样，于是同一锚点图像的匹配能串成多视角轨迹，标定阶段直接使用；
  - 与自由采样的匹配在同一像素上相差中位 0.34 px；每对图像约 0.3 s。
- **AnyLoc 式描述子**：DINOv2 ViT-L/14 的 patch token 做 VLAD，视觉词典在这批图像上用球面 k-means 学出。

**Keble 实测**
- **相机标定**（RoMa，每 4 张取 1 张）：三路鱼眼的重投影 RMS 分别从 0.94 / 0.75 / 1.50 px 降到 0.90 / 0.69 / 1.43 px；时间偏差估计为 1.3 / −0.1 / 0.2 ms（±0.06），与硬件同步一致。
- **跨趟外观检索**：keble-03 的每张图在 keble-02 里找最像的图，相机相距 5 m 内、朝向差 45° 内算命中。两趟起点相距 4.2 m、朝向差 76°，不用任何位姿先验：

  | 词典大小 | 描述子维数 | recall@1 | recall@5 |
  |---|---|---|---|
  | 16 | 16k | 0.75 | 0.91 |
  | 32 | 32k | 0.79 | 0.92 |
  | 64 | 65k | 0.86 | 0.95 |

- **外观回环**（`loops.appearance.enabled`）：
  - **候选**：每隔一个关键帧取最近的一张图算描述子，每帧提出最像的 2 个关键帧（别的趟次，或同一趟里隔开 30 个关键帧以上）。相似度本身分不开真假匹配（真匹配 0.72–0.87，假匹配 0.68–0.80），所以不设阈值，全交给几何验证。
  - **验证**（C++ `VerifyAppearanceLoops`）：外观候选没有可信的位姿初值，不走位置门控和最大修正量检查。两份子图先做重力对齐的粗搜索，每个航向先各取一个假设，再补其他高程；逐个 ICP 精配，最优解要比任何不同的解多对上 3% 的点，之后与几何回环一起过 PCM。
  - **为什么每个航向都要试**：合成车库近似 180° 对称，只取得分最高的几个假设时，对面的错误位姿会胜出。28 对候选（14 对真、14 对来自车库另一头）中有 22 对通过 ICP，PCM 后只剩 14 对真的。
  - **Keble 两趟**（两趟都没有入口位姿；两趟共用一个刚体对齐的 ATE）：

    | 配置 | 联合 ATE |
    |---|---|
    | 不做整趟粗对齐，只有几何回环 | 31 m（两趟错开） |
    | 不做整趟粗对齐，加外观回环（267 个） | 11.2 cm |
    | 整趟粗对齐（4.1） | 7.8 cm |
    | 整趟粗对齐 + 外观回环（259 个） | **6.9 cm** |

    这张表测于 IMU 杆臂修正之前。修正后（9.0）：
    - 整趟粗对齐 5.4 cm；
    - 加外观回环 5.6 cm。

    几何回环已经够用，外观回环的价值在于没有位姿初值时也能找到回环（上表第二行）。

### 9.0 几何精度汇总（2026-10-19，当前默认参数，从头重跑）

### 9.2 FusionPortableV2 地下车库（手持，2026-10-14）

**数据**
- **数据集**：[FusionPortableV2](https://fusionportable.github.io/dataset/fusionportable_v2/) 的 `handheld_underground00`，港科大（广州）地下车库，404 s。
- **设备**：手持多传感器，没有轮速。Ouster OS1-128、STIM300 IMU、双目 1024×768 相机。
- **路线**：约 400 m 单程直走廊，没有回到走过的地方，所以没有真正的回环；起步时设备放在地上，静止约 20 s 后拿起。
- **真值**：Leica 地面扫描合并点云（9564 万点）和 Leica MS60 跟踪仪轨迹（只有棱镜位置）。两者不在同一坐标系，数据集也没给两者之间的变换。

**流程**
1. `convert`：用 `fusionportable_v2_handheld.yaml` 转换，约 3 分钟。
2. `recon` 和 `semantics`：用 `fusionportable_v2_handheld_recon.yaml`。
3. `accept --method auto`：把地图配准到整张真值点云（4 cm 抽稀）上。
4. 把我们的路径变换到真值坐标系，再用 `import-scan` 按路径裁剪、起草真值要素。

**这份数据要求的处理**

| 问题 | 现象 | 处理 |
|---|---|---|
| LiDAR 与 IMU 时钟偏差 | 官方标定文件里没有这一项；偏差随录制段变化，段内还会漂移 | 转换时按段估计（`clock_sync`）；补上这项偏差后，IMU 因子残差中位数从 12.1 降到 3.7 |
| 加速度计零偏和倾斜分不开 | 见 4.3 | 战术级 IMU 先验收紧到 0.03 m/s² |
| 平面 BA 把走廊压弯 | 当时 BA 用 1 m 起的回波；缩短最大量程、按距离和入射角降权（`ba.angular_sigma`）都没用 | 这台设备暂时关闭 BA。另两台手持设备上的原因是近处回波（4.3），新默认 `ba.min_range` 5 m 待在这份数据上复测 |
| 起步放在地上 | 只看开头几帧找不到车体下方的地面 | 地面高度在整段录制中抽 20 帧取中位数（1.26 m）；导航入口取离起点最近的楼层 |
| 没有轮速 | 只能靠匀速模型 | 陀螺运动先验 |
| 真值里没有独立柱 | 两侧是凹进去的车位区，`import-scan` 正确地起草出 0 根柱 | 柱检查点和控制点在这里不适用 |

| 轨迹对跟踪仪，刚体对齐，364 s / 408 m | 纯里程计 ATE 0.50 m（高程 0.39 m）；IMU 图优化 + 回环 ATE 0.42 m，其中高程 0.04 m、水平 0.41 m |

  - BA 关闭；
  - Ouster 的测距噪声；

  - LiDAR 的系统误差。

**复查（2026-10-22）**：从原始 bag 重新转换、重建，用当前代码和默认参数，包括 Ouster 时间字段修复（9.7）与 IMU 杆臂修正（9.6）。

### 9.7 Hilti 2021 Parking Deck（手持，2026-10-16）

**数据**
- **数据集**：Hilti SLAM Challenge 2021 的 `Parking_1`（Hugging Face `Hilti-Research/hilti-slam-challenge-2021`，CC BY-NC-SA 3.0），一座两层的露天停车楼，582 s。
- **设备**：Ouster OS0-64、Alphasense（五路灰度鱼眼 + BMI085）、ADIS16445；Livox MID70 是 `CustomMsg`，未读。
- **真值**：21 个全站仪测量的杆尖位置，分布在两层（高差约 3 m），其中 G5、G20 各测了两次。

**转换（已核对）**
- **外参约定**：`calibration.yaml` 是"子坐标系在父坐标系中的位姿"、四元数 xyzw。三方面互相印证：
  - 侧视相机位于其朝向的一侧；
  - 与 bag 里旧版 `/tf_static` 对比，只差几毫米；
  - 杆尖在 IMU 的 +z 1.67 m 处，说明 Alphasense 倒装、IMU z 轴朝下。
- **IMU 一致性**：
  - ADIS 旋转到 IMU 坐标系后，与 Alphasense 陀螺逐轴相关 ≥ 0.997，延迟 0 ms；
  - Ouster 内置 IMU 按标定旋转后与 Alphasense 的残差为 0.03 rad/s，延迟 0 ms，说明 LiDAR 外参和时钟都正确。
- **起步窗口**：设备从第一秒起就在动，取 2–4 s 最安静的窗口摆正（`--start 2`）。
- **并行转换**：`--jobs 12` 用 4.8 分钟，得到 5804 帧扫描、每路相机 1164 张图。

**转换的问题（已修复）：Ouster 无回波像素的时间字段**
- **现象**：最初的转换结果里有 9 帧扫描，点的时间在帧时间戳之前约 4.1 s；本该在它们位置上的帧缺失，留下 200 ms 的空缺。原始 bag 在这些时刻都是规则的 100 ms 帧。
- **原因**：
  - `stamp: start` 时，帧的结束时间按"表头时间 + 点时间的跨度"计算，跨度原来取自整帧所有像素；
  - Ouster 没有回波的像素（xyz = 0）的 `t` 字段可能是无意义的值（这里约 +4.1 s），把整帧推迟了 4 s；
  - 这些像素随后被距离过滤丢掉，只剩下错位的时间。
- **修法**（`rosbag.decode_sweep`）：
  - 时间跨度只用有效回波计算；
  - 与中位时间相差超过一帧周期的点丢弃；
  - 有回归测试。重新转换后，损坏帧为 0。
- **影响**：原先内置里程计在 106 s 发散，正是一帧损坏的扫描所致，而不是此前判断的"露天楼面几何退化"。FusionPortableV2 的两份数据也是 Ouster，当时用同一段代码转换。地下车库（9.2）已复查：图优化 ATE 从 0.42 m 降到 0.14 m。

## 10. 代码结构

### 10.1 C++ / Python 分工

以下算法**完整地**在 C++（`gr_core`）里实现。Python 只负责：
- 读写文件；
- 把 YAML 配置映射成 C++ 配置结构（`core_config.py`）；
- 按阶段调用。

| 模块 | C++ 入口 | 内容 |
|---|---|---|
| 点云配准 | `registration` | 体素哈希地图、多尺度点到面 ICP、由粗到精 ICP（`icp_multiscale`） |
| 激光里程计 | `imu`、`odometry` | 轮速 + 陀螺运动先验、扫描时间窗内 IMU 去畸变、逐帧配准、关键帧选择与关键帧点云（`OdometryPipeline`） |
| 回环检测 | `keyframes`、`loop_closure` | 位置半径 + 楼层高差门控、Scan Context 排序、子图多尺度 ICP 验证（按查询帧并行）、PCM 一致性筛选 |
| 位姿图优化（含 IMU） | `imu_preintegration`、`pose_graph`、`backend` | 入口 INS / GNSS 锚点（按时间戳用轮速 / 陀螺推到关键帧）；无锚点趟次的整趟粗对齐（`AlignTrips`：重力对齐粗搜索 + 多尺度 ICP）；IMU 预积分因子（流形预积分，含零偏雅可比；惯性"体"的原点在 IMU 处，即杆臂）、每个关键帧的速度与零偏状态、轮速 + 非完整约束的车体速度因子、零偏随机游走；LM 优化；整个阶段一次调用（`run_graph_stage`），以及逐帧位姿修正。加速度计重力因子、扫描到地图精修保留为可选项 |
| LiDAR BA | `plane_factor`、`lidar_ba` | 见 4.1（`RunLidarBa`） |
| 连续时间轨迹（位姿集合） | `trajectory`、`exposure` | 以全部激光帧位姿为节点，节点间用去零偏陀螺和轮速积分并做端点修正（`ContinuousTrajectory`）；用它重新去畸变关键帧（`DeskewKeyframeSweep`）；相机每一行按曝光时刻取位姿（卷帘快门，`CameraExposure`） |
| 相机标定 | `camera_calibration` | 在固定轨迹上联合估计相机时间偏差与外参：多视图特征轨迹 + 三角化路标 + 路标到 LiDAR 面的点面约束，LM + 路标 Schur 消元（`CalibrateCamera`） |
| 地图与动态点判断 | `static_map`、`visibility` | 测量点云（多次观测融合、每点 σ）；法向定向、按趟距离图像可见性投票、自车扫过区域、高度门限，输出"本趟内移动 / 跨趟变化"（`DynamicDetector`） |
| 占据栅格 | `objects`、`occupancy` | 目标框时间线（停放 + 移动轨迹插值）、每帧语义占据与 LiDAR / 相机可见性掩膜（`OccupancyGenerator`） |
| 投影 | `projector`、`labeling`、`raster` | z-buffer 渲染、逐帧标签图、车位 / 标线 / 目标框投影与遮挡、投影一致性分（`FrameLabeler`）、2D→3D 多视角投票（`LabelLifter`）、地面纹理的遮挡渲染；全部按曝光（卷帘快门）投影 |
| 时钟同步 | `clock_sync` | 两个陀螺分窗口互相关（积分后的平均角速度，避免插值相位偏差），每窗口估旋转，稳健拟合偏差与漂移 |
| 与参考点云比较 | `cloud_compare` | 两个重力对齐点云的粗配准（墙面方向定航向的 4 个候选，立面占据图相关定平移，水平面高度直方图定高程），点到参考表面的距离（验收用） |
| 跨视角身份关联 | `identity` | 每帧 2D 掩膜经共享位姿和 LiDAR 地图投到 3D，按已识别点的归属加入身份或合并身份（同一帧的不同掩膜互斥），点按投票得到身份（`IdentityAssociator`） |
| 导航地图 | `nav_map` | 精确欧氏距离变换、Zhang-Suen 细化、骨架提图（节点聚类、毛刺剪枝、二度节点合并）、Douglas-Peucker 简化、Dijkstra 路网（含单行边）、8 邻域栅格 A* |
| 3DGS 支撑 | `gaussians`、`coverage`、`raycast` | 由 LiDAR 测量点生成扁平高斯；沿射线渲染高斯的深度和强度（3DGRT / 3DGUT 式逐高斯求峰值，网格 DDA 遍历），用于强度通道和留出扫描核验；相机覆盖统计（每点有效视角数、最佳分辨率、加权颜色）；训练掩膜；自由空间栅格 |
| 深度先验 | `depth_prior`、`projector` | DA3 深度与 LiDAR 的稳健对齐（在可见地图点上拟合尺度 / 偏移，按网格剔除，只填空洞）；第一表面平均深度 |
| LiDAR-惯性里程计 | `lio` | 迭代误差状态卡尔曼滤波（状态在 IMU 处）：IMU 传播、按 IMU 位姿逐点去畸变、点到面（无平面时点到点）迭代更新；可选零速更新与限速 |

这些 C++ 接口不依赖 Python，可以直接在 C++ 程序里调用。`cpp/gr/e2e_test.cc` 在仿真车库里跑两趟，从里程计、图优化、地图、动态点一直到占据栅格和逐帧标签，全程不经过 Python。

第 8 章新增的 C++ 部分：
- **DA3 深度对齐**（`depth_prior`）：在 LiDAR 点上做稳健尺度 / 偏移拟合，按网格剔除，只填空洞；
- **第一表面深度**（`projector` 的 `RenderSurfaceDepth`）：z-buffer 决定哪层表面在前，深度取该层点的均值，不取最近点；
- **局部平面投影**（`geometry` 的 `ProjectToLocalPlanes`）：3DGS 锚点的去噪；
- **LiDAR-惯性里程计**（`lio`）；
- **3DGS 核验**：沿留出扫描的射线渲染，复用已有的 `GaussianRayRenderer`。

仍在规划中：3DGS 约束用的 LiDAR 表面距离场（现在按表面距离剪枝，没有在训练里按距离场加权）。

Python 部分：
- 数据与标定读写、位姿集合（`recon/pose_set.py`）与产物版本记录（`provenance.py`）、阶段编排；
- 楼层 / 坡道与 BEV；
- 语义规则：结构、标线、车位、目标检测跟踪、车位号、规则、导出；
- 导航地图的分层、路网组装、目标点、地址与 QA；
- 语言路线的特征提取与身份级语言特征（`semantics/language_field.py`）；
- 模型接口与合成真值实现（`models/`）；
- 评测、自检和合成数据；
- PyTorch 部分：
  - 已有：DA3（`models/da3.py`）、RoMa / DINOv2（`models/dino.py`）的推理，gsplat 3DGUT 训练（`recon/gs.py`）与正射 / 核验（`recon/gs_verify.py`）；

## 11. 工程约束

### 11.1 算力

- gsplat 依赖 CUDA。3DGS / 语言高斯训练，以及 DA3、SAM 的批量推理，都放在 GPU 服务器上。
- 本机（Apple M2，无 CUDA）跑 C++ 几何、合成数据端到端和小模型冒烟测试。本机 PyTorch 是 2.0.1（MPS 可用），跑新模型前可能需要升级。

### 11.3 风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 3DGS 几何本身不是测量级 | 漂浮物、地面下的倒影几何、弱纹理墙面起伏 | LiDAR 锚定、自由空间剪枝、禁止地面以下的高斯、来源标记；测量只用 L / G |
| DA3 误差随距离增长，分辨率低 | LiDAR 空洞处几何不准 | 只作先验：与 LiDAR 对齐、按置信度加权，标为 P |
| 车库光照 | 低照度噪声、运动模糊、灯光频闪、自动曝光跳变 | 采集规范；逐图曝光补偿；建模运动模糊或剔除模糊帧 |
| 外观单一、结构重复 | SfM 式对应失败（LetsGo 也指出这一点）；回环误判 | 位姿只来自 LiDAR-惯性；回环加外观和文字候选，由 ICP + PCM 判定 |
| CLIP / SigLIP 对细长、扁平、文字类别弱 | 标线、车位号、细杆识别差 | 正射影像上分割 + OCR + 规则；逐类标定阈值；用审核后的标签训练点云网络 |
| 跟踪式身份在大场景断链 | 身份不一致，ILGS 失效 | 几何关联 + DINO |
| 相机覆盖不全 | 顶板、柱背面、管线没有外观监督，3DGS 剪枝会删掉 | 冻结高斯、LiDAR 强度通道、覆盖率进 QA |
| 车位层质量 | 假车位切断车道，漏检车位没有目标点 | 推断要有证据；桥列入审核；QA 逐车位规划 |
| 规模 | 显存和时间；稠密 BA 约 2500 关键帧以内 | 分块训练；身份级语言特征；分层 BA |
| 许可证 | 量产不可用 | 见 11.2 |

## 12. 已知限制与下一步

**下一步**
- 本机可做：
  - 开阔场地按车位排的入口线偏移出车道中线，与中轴线合并，替代网状骨架；
  - 车端在这张地图里的定位。
- 需要模型下载许可：OCR 模型（真实数据的车位号）。
- 需要 GPU 服务器：
  - 3DGS 训练：冻结与保护策略、强度损失、核验流程、覆盖率 QA；
  - DA3 深度对齐；
  - 语言高斯；
  - 真实模型适配器：SAM 2 / SAM 3、SigLIP 2、DINO / RoMa、Depth Anything 3、OCR。
- 之后：点云网络（用审核后的 3D 标签训练），补相机盲区，并作为新车库的第二意见。

**导航**
- 单行方向未知（地面箭头尚未识别），所有边都是双向。
- 车库出入口、限高标志、车位属性（充电、无障碍、专用）还没有。
- 车位占用只是采集时刻的，导航要接实时状态。
- 真实场地的车位检测仍有漏检：隔线碎成多段时整排丢失。

**位姿与标定**
- LiDAR–IMU 外参未估计（杆臂已建模，9.6）；加计的标度和轴间误差未建模，Keble 上只加 IMU 因子时仍比纯里程计差（9.6）。
- LiDAR 时间偏差只在转换时按段估计，前提是雷达有内置 IMU；没有时要在后端作为待估参数。
- LiDAR BA 把位姿块当稠密矩阵求解（先消去惯性状态），适用于约 2500 个关键帧以内。更大的车库要走稀疏求解（已有，但填充多、较慢）或分层 BA（HBA 式子图）。
- 回环候选有 Scan Context 和 DINO 外观描述子（8.4，默认关闭，需要 GPU），还没有 OCR 文字候选。
- 地图的绝对坐标只由入口 INS / GNSS 决定，测量级成果要用控制点定坐标系。

**真实数据（FusionPortableV2）**
- 用新默认（`ba.min_range` 5 m）复测手持数据的 BA；原先怀疑的线束仰角误差在另两台手持设备上没有得到印证（4.3）。
- 找一份有厘米级参照的车载数据验证绝对精度，例如全站仪控制点或密集地面扫描。
- IMU 噪声和零偏先验改为按传感器等级配置。
- 没有柱的车库需要别的检查点，例如墙角、车位角或全站仪靶标（`points.csv`）。
- 长走廊需要控制点或回环来约束航向。

**真实数据（手持设备：Mandeye、Oxford Spires、Hilti）**
- **BA 的近处回波**（已解决，4.3）：近处回波的毫米级偏差曾把手持走廊压弯；BA 现在只用 5 m 起的回波。长走廊竖向弯曲的约束本来就弱，其他系统误差仍可能顺着这个模态放大，验收时要看水平面误差的空间分布，而不只是 p95。
- **无锚点趟次的粗对齐**（已实现，4.1、9.6）还有两处不足：
  - 各层完全相同、某一趟只走了一层时，几何上分不出楼层，这一趟不会被放置。要靠楼层标志的 OCR 或其他外观线索；
  - 只检验前 8 个候选，柱网很规整时，正确航向可能排不进去。回环候选也可以再加不门控的全局描述子。
- **手持设备的动态点**（已处理，9.5）：三台手持设备在最小距离以外都扫不到操作员；误报来自按车宽设计的自车空间规则和语义的拖影规则，已按设备类型修正。伪"移动轨迹"仍待处理（跟踪器需要按观测完整度处理框中心的漂移）。
- **轨迹对照工具**：对 TUM 参考轨迹（带 body→LiDAR 外参）和 Hilti 的稀疏 3-DoF 点的评测，现在还是临时脚本，要并入 `eval/`。
- **LiDAR-惯性里程计**（已实现，`odometry.use_lio`，9.7）：Hilti Parking_1 上杆尖 RMSE 0.34 m（IMU 杆臂修正后；修正前 1.03 m），剩余是无控制点时 500 m 路线的航向漂移。下一步：
  - 用 Livox MID70 的远距离前视回波补约束（`CustomMsg`，尚未读）；
  - 用相机（DINO 匹配）补回环；
  - 用全站仪点做控制点。
- **重新检查 Ouster 数据的转换**：无回波像素的时间字段曾让个别帧错位 4 s（9.7，已修复）。
  - FusionPortableV2 地下车库（9.2）已重跑：0.42 → 0.14 m；
  - 室外无人车数据（9.3）还没有重跑。

**语义**
- 标线只处理与柱网对齐的直线：斜列车位需放宽 `markings.max_axis_angle`；箭头和文字尚未识别。
- 斜列车位和带横线的车位（T / L 形）还没有专门处理。
- 入口线被遮挡多的排只有很少的可靠端点（small 数据里有一排偏 4–5 cm）。
- 坡道只建模为平面，螺旋坡道需要分段平面或曲面。
- 语言路线：
  - 相机看不到的面（车顶等）没有 2D 依据；
  - 物体与地面接触处有边界渗漏；
  - 逐帧标签由点云渲染，边界不如 2D 掩膜。
- 占据 IoU 还没有评测。

**工程**
- **耗时**：最耗时的是逐帧标签、语言路线、图优化、相机标定和地面纹理。可以这样减少：
  - 只给需要的帧出标签（`frames.frame_stride`、`features.frame_stride`）；
  - 减小回环检测密度（`loops.stride`）；
  - 减少标定轨迹数（`calibration.tracks_per_anchor`）。
  - 逐帧标签和地面纹理的 C++ 调用都释放了 GIL，还可以按帧多线程并行（尚未做）。
- C++ 核心的文件读写目前由 Python 完成。若要不带 Python 部署，需要补一个 C++ 数据读写层，算法接口不用改。
- 部分旧 Python 模块（markings、structure、objects4d、levels、bev 等）尚未改写成 Google 风格。
- 合成路线的转弯很急（每帧最多 45°），转角处的单帧旋转误差可达 1–3°；真实 10 Hz 数据的转角误差会小得多。
