# 多层地下车库 3D 高精度重建 + 自动语义标注：方案 v2

2026-10-12 修订。本文件覆盖原方案的第四部分（车载重建）、第五部分（自动语义标注），以及它们依赖的标定和验收。相对 v1 的变化：

- **几何**：在 LiDAR-惯性骨架之上加 DA3 稠密深度和 3DGS，用来补细节和外观。
- **语义**：用 SAM 掩膜加 CLIP / SigLIP 语言特征，按 ILGS（Identity-aware Language Gaussian Splatting，ICCV 2025）的方法建立身份一致的 3D 语言场。
- **跨视角几何对应**：用 DINO。

v2 的落地顺序见第 10 节；第 1、2、4 步已实现（10.1、10.2），第 3、5 步需要 GPU 和真实数据。

## 1. 原则

1. **几何是骨架，必须达到测量级。** 位置和尺度由 LiDAR + IMU 决定。DA3 和 3DGS 只补 LiDAR 没测到的细节和外观，不得移动 LiDAR 已测的表面。
2. **所有数据共用一套位姿。** 以下数据都从同一个位姿集合取位姿：LiDAR 点、每台相机的每一行像素、DA3 输入、3DGS 训练视角、语义渲染、占据、矢量。
3. **语义分三路。** 2D 视觉大模型（SAM、CLIP / SigLIP、OCR）负责认出"是什么"。3D 表示（语言高斯场、点云网络）和几何规则负责让结果在各视角间一致。

## 2. 总体数据流

```
采集（LiDAR / IMU / 轮速 / 双目 / 鱼眼）
  │
  ▼
[A] 骨架（C++）：里程计 → 回环（Scan Context + DINO + OCR）→ 位姿图（IMU 预积分、标定参数）
  │             → 连续时间轨迹 → LiDAR BA → 测量点云
  │   输出：唯一的位姿集合（pose_set_id）
  ▼
[B] DA3：位姿条件的多视角深度 → 与 LiDAR 对齐 → 稠密深度先验
  │
  ▼
[C] 3DGS（gsplat + 3DGUT）：LiDAR 锚定，鱼眼 + 卷帘快门，几何受约束
  │   → 核验（C++）→ 表面、正射影像、任意视角渲染
  ▼
[D] 2D 基础模型：SAM 2 多粒度掩膜、SigLIP 2 / CLIP 掩膜嵌入、OCR、DINO 稠密特征
  │
  ▼
[E] 身份关联（几何投影 + DINO）→ ILGS 式语言高斯（几何冻结）→ 3D 类别与实例
  │
  ▼
[F] 规则约束与矢量化、逐帧标签渲染、LiDAR 点标签、占据 → 导出与 QA
```

## 3. 几何

### 3.1 分工

| 组件 | 负责 | 不负责 |
|---|---|---|
| LiDAR + IMU + 轮速 | 位姿、绝对尺度、主体表面（墙、柱、地面、顶板） | 纹理；LiDAR 没测到的区域 |
| DA3（及双目） | LiDAR 空洞处的稠密深度先验；3DGS 的初始化和正则 | 位姿、尺度、最终几何 |
| 3DGS | 细节（管线、喷淋、细杆、标志牌、边缘）、外观、正射影像、任意视角的深度 / 法向 / 标签渲染 | 改动 LiDAR 已测的表面 |
| DINO | 跨视角、跨趟的对应关系 | 直接输出位姿 |

LiDAR 空洞指累积地图之后仍然没测到或采样很稀的地方：线束间隙、车与车之间、细杆和管线、标志牌边缘、背向车道的柱面、顶板上的设备。

### 3.2 骨架（C++，补齐 v1 审计的缺口）

3DGS 对位姿误差比点云地图敏感得多，误差会直接表现为模糊和重影：

- 相机时间偏差 5 ms、车速 4 m/s，就是 2 cm 错位；
- 0.1° 姿态误差在 10 m 处是 1.7 cm。

所以骨架的以下几项是 3DGS 的前提：

- IMU 预积分因子和零偏估计；
- 连续时间轨迹（关键帧位姿 + IMU 高频插值），并用它重新去畸变所有入图扫描；
- 平面约束的 LiDAR BA，替换现在的"扫描到地图精修"；
- 体素内多次观测加权融合，每个点带不确定度 σ；
- 标定参数作为全局变量进入位姿图：LiDAR–IMU 外参、相机外参、相机时间偏差、卷帘行时间。相机侧的约束来自 DINO 对应 + LiDAR 深度的重投影残差（第 5 节）；
- 回环候选三路：Scan Context（几何）、DINO 全局描述子（外观）、OCR 读出的车位号 / 分区号（文字），最后仍由多尺度 ICP 和 PCM 判定。

### 3.3 DA3

- **位姿条件模式。** 把同一套位姿（world→camera）和内参传给 DA3，并设 `align_to_input_ext_scale=True`。这样输出深度按我们的位姿定尺度，DA3 自己估计的位姿会被替换掉。自估位姿只做诊断：与我们的位姿差别大，说明标定或同步有问题。
- **输入。**
  - 鱼眼图先切成几张虚拟针孔视图（DA3 只接收针孔内参）；双目两路一起输入。
  - 默认处理分辨率是长边 504 像素，所以 DA3 深度只是低分辨率先验，细节靠 3DGS 在原始分辨率上训练。
- **与 LiDAR 对齐（C++）。** 每帧在 LiDAR 投影深度上做稳健的尺度 / 偏移拟合，残差超限的帧或区域丢弃。输出深度、置信度和来源标记，只在 LiDAR 空洞处使用。
- **模型选择。** 可商用的有两组：
  - DA3-BASE / DA3-SMALL：任意视角，支持位姿条件，Apache 2.0；
  - DA3METRIC-LARGE、DA3MONO-LARGE：单目，Apache 2.0。

  DA3-GIANT / LARGE / NESTED 以及前馈 3DGS 输出是 CC BY-NC 4.0，只用于研究对照。

### 3.4 3DGS

- **实现。** 用 gsplat（Apache 2.0）的 3DGUT 模式：直接在原始鱼眼图上训练，支持卷帘快门，不需要去畸变。不用 Inria 原版光栅器（非商用许可）。
- **相机。** 每一行像素的位姿 = 位姿集合在该行曝光时刻的值 ∘ 相机外参。关闭逐帧位姿优化。
- **初始化。** 用 LiDAR 测量点和法向生成扁平高斯；DA3 点只补 LiDAR 空洞。
- **损失。**
  - 光度：L1 + D-SSIM，每张图一组曝光 / 白平衡补偿；
  - LiDAR 深度：渲染深度对 LiDAR 投影深度，或沿 LiDAR 射线渲染（参考 SplatAD）；
  - DA3 深度：只用在 LiDAR 空洞，按置信度加权，随训练衰减；
  - 法向：平面区域用 LiDAR 平面法向；
  - 扁平化（最小尺度轴趋零）和多视角几何一致（参考 PGSR）。
- **骨架约束。** C++ 预先算好 LiDAR 表面距离场、自由空间栅格（复用 `FreeSpaceCarver`）和各层地面高度，训练时在 GPU 上查表。
  - 落在 LiDAR 表面附近的高斯受锚定惩罚，偏离超过容差的剪掉；
  - LiDAR 射线穿过的自由空间里不允许有高斯，用来清除漂浮物；
  - 地面以下不允许有高斯，否则环氧地坪的倒影会在地面下长出"镜像"几何。
- **掩膜。** 屏蔽三类区域：移动目标（动态点判断 + 4D 框投影）、自车车身、过曝的灯具。
- **分块。** 按楼层和坡道分区，约 40 m 一块、带重叠，并行训练。合并时每个高斯归属于它所在块的核心区。
- **采集要求（写进采集规范）。**
  - 曝光时间上限：4 m/s、20 ms 曝光就有 8 cm 运动模糊；
  - 增益上限、防频闪。
  - 运动模糊也可以建模：用连续轨迹在曝光窗内取多个位姿渲染。

**LiDAR 要素的覆盖（2026-10-15 补充）。** 3DGS 不单独覆盖全部 LiDAR 要素：相机拍不到的地方没有外观监督，标准的不透明度重置和剪枝还会把这些高斯删掉。实测地下车库（手持，前向双目）只有 54% 的 LiDAR 点被相机拍到过，顶板 13%、柱 40%、管线 43%。因此：

- **全部 LiDAR 点都生成锚定高斯。** 有效视角（曝光正常、未遮挡、非掩膜）不足 3 个的标为"冻结"：几何和不透明度保持初值，不参与不透明度重置和剪枝，颜色先用反射强度代替，标记为"无外观"。
- **高斯带 LiDAR 强度通道。** 沿 LiDAR 射线渲染强度（参考 SplatAD），标线可以从同一个模型里取；相机看不到的高斯也能由 LiDAR 监督强度。
- **跨趟变化的物体**按趟生成专属高斯（只在本趟的视角里参与渲染），或在图像中屏蔽。
- **相机覆盖率按类别进入 QA**，作为 3DGS 的验收项；同一工具可在已有轨迹上评估设想中的相机布置（环视鱼眼、朝上相机）。
- C++ 已实现：锚定高斯初始化、沿射线渲染（深度、强度、主导高斯）、相机覆盖、训练掩膜、自由空间栅格（`gaussians`、`coverage`）。训练部分（gsplat）待 GPU。

### 3.5 测量级的定义与核验

每个 3D 元素带来源标记和不确定度：

| 标记 | 来源 | 用途 |
|---|---|---|
| L | LiDAR 实测，多次观测融合 | 测量级，进入矢量测量 |
| G | 3DGS 几何，经留出的 LiDAR 扫描或多视角一致性验证 | 测量级，σ 按核验结果给出 |
| P | 仅有先验（DA3，或未通过核验的 3DGS） | 只用于可视化和完整度，不进入矢量测量 |

核验（C++）：

- 3DGS 渲染深度对留出的约 10% LiDAR 扫描的误差；
- 高斯表面到 LiDAR 地图的距离分布，按区域出偏差图；
- 对手持真值：控制点配准，检查点评测（RMSE、CE90），按 L / G / P 分开统计。

产出：

- 带 σ 和来源标记的测量点云；
- 表面网格（渲染深度做 TSDF 融合）；
- 3DGS 模型；
- 每层的正射影像，替代 v1 的 5 cm 地面栅格和地面纹理；
- 每台相机任意时刻的深度和法向渲染，逐帧标签的遮挡判断改用它。

## 4. 语义

### 4.1 ILGS 要点

- **表示。** 每个高斯在 3DGS 属性之外，再加：
  - 3 维语言嵌入：CLIP 特征经自编码器压缩，沿用 LangSplat；
  - 16 维身份嵌入。
- **训练目标。**
  - RGB：L1 + D-SSIM；
  - 渲染的语言特征图对 CLIP 特征图：L1；
  - 渲染的身份特征图对多视角一致的身份标签：分类交叉熵；
  - 身份感知一致性损失：同一身份的语言嵌入拉近（L_same），不同身份推远（L_diff）。
  - 训练中按交叉熵阈值剔除不可靠的身份区域。
  - 几何属性与语言、身份嵌入端到端联合训练。
- **推理（渐进掩膜扩展）。** 按身份分段，算每段语言特征与文本的余弦相似度。从相似度最高的种子段开始，逐步并入与种子相似度相差不到 10% 的相邻段，这样边界更准。
- **结果。** LERF-mask 上平均 mIoU 80.5（LangSplat 57.6，Gaussian Grouping 72.8）；3D-OVS 上平均 94.4。
- **局限。**
  - 论文场景是桌面尺度，位姿来自 SfM。
  - 多视角一致的身份标签由零样本视频跟踪器 DEVA 生成。作者在补充材料中指出，复杂场景里跟踪标签会出错，方法也只针对静态场景。
  - 代码基于 Inria 原版 3DGS 和 Gaussian Grouping 的官方实现。

### 4.2 三路分工

| 路 | 组件 | 负责 |
|---|---|---|
| 2D 基础模型 | SAM 2 多粒度掩膜；SigLIP 2（或 CLIP）掩膜嵌入；OCR；DINO 稠密特征 | 认出"是什么"，读出文字 |
| 3D 表示 | ILGS 式语言高斯（几何冻结，只训练语义属性）；之后蒸馏到点云网络 | 跨视角一致、实例身份；补相机看得少的区域 |
| 几何规则 | 车位排列、柱网、标线平行 / 垂直、编号连续；类别的几何合理性（如挡轮器贴地且低于 0.2 m、标志牌高于 1.8 m） | 约束和校验，不单独判类 |

语言模型推荐 SigLIP 2：多语言（中文提示词可直接用），定位和稠密特征比 CLIP 好，Apache 2.0。

### 4.3 车库尺度的三处改造

先按论文原样实现一版（3 维语言 + 16 维身份）作为基线，再与下面的改造对比。

1. **身份标签用几何关联，不用视频跟踪。**
   - 问题：几千帧、结构重复的车库里，DEVA 这类跟踪器会断链或串号。
   - 做法：这里有共享位姿和 LiDAR / 3DGS 深度。把每帧 SAM 掩膜投到 3D（C++ 投影 + z-buffer），按 3D 重叠建关联图，再做图聚类得到全局身份。车窗、反光地面这类几何不可靠的地方，用掩膜的 DINO 特征相似度补充。
2. **语言特征按身份存全维。**
   - 问题：3 维自编码器压缩会损失开放词汇能力。
   - 做法：身份一致性损失本来就把同一身份的语言嵌入拉向同一个值，所以直接给每个身份存一个全维 SigLIP 嵌入，高斯只存身份。这个嵌入是多视角加权平均，距离近、正对、未遮挡、掩膜完整的视角权重高。
   - 地面、顶板、墙这类没有明确个体的"背景类"，保留逐高斯的低维语言场。
3. **几何冻结。** 论文是几何与语义端到端联合训练。这里改为只优化语义属性，语义损失不能把高斯从 LiDAR 锚定的位置拉走。

### 4.4 查询与车库分类

- **提示词与阈值。** 每个类别写一组中英文提示词；SigLIP 的 sigmoid 分数用少量人工标注帧逐类标定阈值。
- **长尾目标。** 开放词汇查询用于消防栓箱、充电桩、施工围挡等长尾目标，结果经审核后再并入分类表。
- **文字。** 车位号、分区号不靠 CLIP / SigLIP，靠 OCR，再用"同排编号连续"规则修正。
- **移动目标。** 移动目标和跨趟变化的车辆不进共享的语言场（ILGS 只处理静态场景），由 4D 框负责；它们的类别用 SigLIP 对各帧掩膜投票得到。
- **地面要素。** 标线、车位线和地面文字在 3DGS 渲染的正射影像上做分割、语言查询和 OCR（俯视、无畸变、公制尺度），结果再回投到原始帧核对。

### 4.5 输出与一致性

- **3D 标签。** 每个高斯和每个 LiDAR 点的类别、实例、置信度。
- **逐帧标签。** 用同一个语言高斯场，在每台相机的每一帧渲染语义图和实例图（3DGUT 直接渲染鱼眼），遮挡由渲染深度决定。
- **跨视角一致率。** 渲染出的标签与该帧 2D 模型原始结果的一致程度；冲突区域进入人工审核。
- **矢量。** 车位和标线在正射影像边缘 + 3D 点上做最小二乘拟合，再加规则约束。
- **点云网络。** 例如 Point Transformer V3，用审核过的 3D 标签训练。它补全相机覆盖少的区域，也作为新车库的第二意见。

### 4.6 导航语义（2026-10-15 补充）

带语义的重建结果要直接服务导航，例如"去 B2 C 区 105 号车位"。需要四样东西：

- **地址。** 楼层名、分区、车位号（OCR + 同排编号连续），以及从文字查询到车位的索引。
- **目标点。** 每个车位的停车位姿（车头进、倒车进）、车道上的接近点及车道朝向、入口节点。
- **不穿墙的路网。** 障碍按几何判定（车辆高度带内的静态点，不只看类别），类别只用于分层（固定结构、悬挂结构、停放车辆、低矮可越过物）。车道中线取与障碍保持"半车宽 + 余量"的可行驶区骨架，坡道连通楼层；误检车位或窄点截断的路网用栅格 A* 补桥并列入审核。
- **交付与 QA。** ROS nav2 栅格地图、路网与目标点（JSON / GeoJSON）、Lanelet2 车位带编号；对每个车位规划并检查可达性、是否碰到障碍、最小间距。

尚缺：按车位排生成车道线（开阔场地）、单行方向（箭头识别）、出入口与限高、车位属性、实时占用、车端在地图中的定位。

## 5. DINO：几何对应

| 用途 | 做法 |
|---|---|
| 相机标定与时间同步 | DINO 稠密匹配做粗对应，再细化到亚像素（RoMa 式：DINOv2 粗匹配 + 卷积特征细化）。结合 LiDAR 深度构造重投影残差，只优化外参、时间偏差、卷帘行时间 |
| 回环与多趟对齐 | DINO 全局描述子（AnyLoc 式聚合）给出外观候选，与 Scan Context、OCR 文字一起排序 |
| 语义身份关联 | 掩膜级 DINO 特征相似度，补充 3D 重叠关联（4.3） |
| 手持真值配准 | 手持设备带相机时，用 DINO 匹配给初值，再 ICP 到真值点云 |
| 跨趟变化（可选） | 3DGS 渲染图与新一趟图像的 DINO 特征差，作为变化候选 |

- **精度。** DINO 的 patch 步长是 14 或 16 像素，直接用只够做粗对应；用作几何约束之前必须细化到亚像素。
- **复用 DA3 特征。** DA3 的编码器本身是 DINO 结构，可以评估直接复用它的中间特征（`feat_layer`）做对应，省一次 DINO 推理。
- **许可证。** DINOv2 是 Apache 2.0。DINOv3 是 Meta 自定义许可，可以商用但有限制条款，量产前需法务确认。

## 6. 一套位姿的工程保证

- **位姿服务。** 以下参数作为一个整体，带版本号 `pose_set_id`：连续时间轨迹 world_from_vehicle(t)、各传感器外参、时间偏差、卷帘行时间。
- **只从这里取位姿。** LiDAR 去畸变、DA3 输入、3DGS 训练视角、语义渲染、占据、逐帧标签、矢量都通过位姿服务取位姿。
- **修正只回到位姿图。** DINO 重投影残差或 3DGS 光度残差发现的位姿、标定问题，只能作为因子回到位姿图重新求解并生成新版本。任何模块不得私自优化位姿。
- **版本一致。** 每个产物记录 `pose_set_id`。版本不一致的产物 QA 直接拒收，下游阶段自动失效重跑。

## 7. 评测与验收

门槛为初定值，需在手持真值车库上标定。

| 类别 | 指标 | 初定门槛 |
|---|---|---|
| 骨架 | 检查点 RMSE / CE90（手持真值）、多趟重复性、平面厚度 | 检查点 RMSE ≤ 2 cm |
| 3DGS 几何 | 留出 LiDAR 扫描的深度误差；表面到真值的距离，按 L / G / P 分开 | G 类 p95 ≤ 3 cm |
| 3DGS 外观 | 留出帧的 PSNR / SSIM / LPIPS | 用于正射影像质量把关 |
| 语义 | 3D mIoU / mBIoU、逐帧 mIoU、实例 AP、跨视角一致率 | 按类别设定 |
| 矢量 | 车位角点、标线、柱中心的检查点误差；编号正确率 | 角点 RMS ≤ 2 cm |

## 8. 工程落地

### 8.1 阶段

| 部分 | 阶段 |
|---|---|
| 重建 | odometry → graph（IMU 预积分、标定参数、BA）→ trajectory（连续轨迹、重新去畸变）→ map → depth_prior（DA3）→ gs（分块训练）→ gs_verify → ortho |
| 语义 | features（SAM、SigLIP、OCR、DINO）→ identities（几何 + DINO 关联）→ lang_field（ILGS 式训练）→ query（类别与实例）→ vectors（标线、车位、柱，规则约束）→ objects → occupancy → frames（渲染逐帧标签）→ rules → export |

### 8.2 C++ / Python 分工

沿用"核心几何算法全部在 C++"的约定。

- **C++（gr_core 新模块）：**
  - 位姿与标定：IMU 预积分、连续时间轨迹、LiDAR BA、标定因子；
  - 深度与高斯：DA3 深度对齐；高斯几何约束用的距离场、自由空间栅格、地面高度；
  - 语义与核验：身份关联（掩膜投影重叠图）、几何核验、矢量拟合。
- **Python / PyTorch：** 模型推理（DA3、SAM 2、SigLIP 2、DINO、OCR）；gsplat 训练（3DGS 和语言 / 身份属性）；阶段编排。
- **模型接口。** 放在独立的 `garage_recon/models/` 包里（标定和语义都要用）：`Segmenter2D`、`LanguageEncoder`、`DenseFeatures`、`Matcher`、`DepthPrior`、`OcrReader`。合成数据上先用真值实现（`models/oracle.py`：真值掩膜、带混淆的语言嵌入、真值对应、真值深度、真值车位号）打通整条链路。
- **语义载体可替换。** 身份关联、身份级语言特征、渐进扩展这些逻辑不依赖高斯。量产用高斯；没有 GPU 的环境（如本机测试）用 LiDAR 点 / 体素作载体，配合现有的 C++ z-buffer 渲染。

### 8.3 算力

- gsplat 依赖 CUDA。3DGS / 语言高斯训练，以及 DA3、SAM 的批量推理，都放在 GPU 服务器上。
- 本机（Apple M2，无 CUDA）跑 C++ 几何、合成数据端到端和小模型冒烟测试。本机 PyTorch 是 2.0.1（MPS 可用），版本较旧，跑新模型前可能需要升级。

## 9. 风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 3DGS 几何本身不是测量级 | 漂浮物、地面下的倒影几何、弱纹理墙面起伏 | LiDAR 锚定、自由空间剪枝、禁止地面以下的高斯、来源标记；测量只用 L / G |
| DA3 误差随距离增长，分辨率低 | LiDAR 空洞处几何不准 | 只作先验：与 LiDAR 对齐、按置信度加权，标为 P |
| 车库光照 | 低照度噪声、运动模糊、灯光频闪、自动曝光跳变 | 采集规范；逐图曝光补偿；建模运动模糊或剔除模糊帧 |
| 外观单一、结构重复 | SfM 式对应失败（LetsGo 也指出这一点）；回环误判 | 位姿只来自 LiDAR-惯性；回环加外观和文字候选，由 ICP + PCM 判定 |
| CLIP / SigLIP 对细长、扁平、文字类别弱 | 标线、车位号、细杆识别差 | 正射影像上分割 + OCR + 规则；逐类标定阈值；用审核后的标签训练点云网络 |
| 跟踪式身份在大场景断链 | 身份不一致，ILGS 失效 | 几何关联 + DINO |
| 规模 | 显存和时间 | 分块训练；身份级语言特征 |
| 许可证 | 量产不可用 | 见 8.4 |

## 10. 实施顺序

1. **骨架补齐**（本机可做，在合成数据上验证）：
   - 位姿服务和 `pose_set_id`；
   - 连续时间轨迹与重新去畸变；
   - IMU 预积分与零偏；
   - 标定参数入图；
   - 同时补齐评测指标。
2. **模型接口与真值实现**（本机）：
   - DA3 / SAM / SigLIP / DINO / OCR 的接口；
   - 用合成真值打通身份关联、身份级语言特征、逐帧渲染标签和跨视角一致率；
   - 语义载体先用 LiDAR 点。
3. **GPU 服务器**：
   - DA3 深度对齐；
   - gsplat + 3DGUT 的 LiDAR 锚定 3DGS 和几何核验；
   - 语言高斯；
   - 在真实数据上调参（可先用公开的车库数据，如 LetsGo 的 GarageWorld，若已发布）。
4. **测量级验收**（已实现，见 10.2）：手持真值导入、控制点 / 检查点报告；LiDAR BA；正射影像上的矢量拟合。
5. **点云网络**：用审核后的 3D 标签训练，作为新车库的第二意见，并补充相机盲区。

### 10.1 进度（2026-10-12）：第 1、2 步已实现

代码见仓库 README。合成数据现在带有传感器误差：
- 每趟 IMU 零偏（陀螺约 0.05°/s，加计约 0.065 m/s²）；
- 相机卷帘快门（读出 25 ms）；
- 相机时间偏差 6–16 ms；
- rig.yaml 外参误差 0.3° / 15 mm。

下面的数字都在这份数据上测得（small：两层 + 坡道、两趟，256 px 鱼眼）。

| 项 | 做法 | 结果 |
|---|---|---|
| IMU 预积分与零偏 | C++ 流形预积分；每个关键帧带速度和零偏；轮速 + 非完整约束 | 零偏误差：陀螺 ≤ 0.003°/s，加计 ≤ 0.0013 m/s² |
| 连续时间轨迹、重新去畸变 | 全部激光帧为节点，节点间用去零偏陀螺和轮速；所有关键帧用它重新去畸变 | 与 v1（重力因子后端）相比：ATE 3.6 → 2.2 cm，姿态误差均值 0.16° → 0.06°、最大 0.28° → 0.16°，地图 p90 4.4 → 2.0 cm |
| 位姿集合 | `pose_set_id` / `trajectory_id`，所有阶段只从它取位姿并记录版本；自检列出过期产物 | 16 个阶段版本一致 |
| 相机标定入"图" | 固定轨迹，联合估计时间偏差和外参；多视图轨迹 + 路标点面约束 | 外参旋转 0.3° → ≤ 0.013°，平移 15 → ≤ 4 mm，时间偏差误差 10–14 → ≤ 1.4 ms |
| 卷帘快门投影 | 每一行按曝光时刻取位姿（`CameraExposure`），用于 z-buffer、逐帧标签、地面纹理、身份关联 | 真值点重投影误差（v1 → v2）2.11 → 0.90 px，p95 6.1 → 2.7 px |
| 模型接口与真值实现 | `models/`：分割、语言编码、稠密特征、匹配、深度、OCR | 合成数据端到端跑通 |
| 身份关联（替代视频跟踪） | C++：几何投影 + 合并 + 同帧互斥 + 法向背面剔除 | 身份纯度 0.90 |
| 身份级语言特征 | 多视角加权平均，与分类表提示词比较 | 点级准确率 0.84（规则路线 0.83），mIoU 0.67（规则 0.74）；跨视角一致率 0.85 |

几点结论：

- **IMU 噪声要用"等效值"**：
  - 噪声密度按传感器白噪声设置时，仿真 IMU 的系统误差（半个采样的时间错位、数值微分）会把轨迹拉偏。陀螺 0.01 rad/s/√Hz、加计 0.2 m/s²/√Hz 最好，与 VINS 等系统的做法一致。
  - 实车应按 Allan 方差加放大系数标定。
- **轮速的非完整约束要放宽**：车体坐标系与运动方向不严格一致（转弯、坡道衔接、侧滑）。侧向 σ 从 0.05 放宽到 0.3 m/s 后：
  - 理想数据上 ATE 3.9 → 2.2 cm、地图 p90 3.5 → 2.0 cm，追平并超过 v1；
  - 有误差的数据上同样改善。
- **时间偏差是"等效"参数**：1.4 m/s 时，1 cm 沿行驶方向的轨迹误差相当于 7 ms。轨迹 ATE 6.8 cm 时偏差约 5 ms，2.2 cm 时 ≤ 1.4 ms。
  - 用真值轨迹标定时无偏；用估计轨迹时，偏差随轨迹精度变化。
  - 测量级的相机几何仍应使用硬件同步（PTP / 触发）。
- **身份关联必须用法向剔除背面**：否则楼板上下两面会被当成同一物体（上层地面与下层顶板合并）。
- **还没解决的**：
  - 相机看不到的面（车顶等）没有 2D 依据，车辆点有 25% 未标注，留给点云网络（第 5 步）；
  - 物体与地面接触处的边界渗漏；
  - 坡道连接的两层之间约 2 cm 的相对高程偏移（第 4 步已用 LiDAR BA 解决，见 10.2；当时以为车位角点误差来自它，实际主要来自线端点和柱面量测）；
  - LiDAR–IMU 外参未估计；占据 IoU 未评测；真实模型适配器属于第 3 步。

### 10.2 进度（2026-10-13）：第 4 步已实现

数据同 10.1（small，有传感器误差）。下表对比第 1–2 步的算法与第 4 步，两边都已修正本轮发现的入口锚点时间戳、第一帧去畸变和 BEV 物体高度栅格的问题。验收用模拟的手持真值：手持扫描仪自身坐标系，另一批停放车辆，毫米级噪声和少量 SLAM 形变；控制点为每层柱网四角的柱，其余柱作检查点。

| 项 | 做法 | 结果（第 1–2 步 → 第 4 步） |
|---|---|---|
| 平面约束的 LiDAR BA | C++：自适应八叉树找各关键帧共有的平面（混面体素切分）；每个关键帧在平面上的点存一、二阶矩，平面参数 Schur 消去（BALM 式代价）；与 IMU、轮速、里程计、回环、锚点因子联合 LM；位姿块稠密求解（先消去惯性状态）；取 30 m 内的回波，2 轮 | 检查点（柱）RMSE 1.6 → 0.4 cm；两层高程偏差 −0.8 / +0.9 → ±0.1 cm；刚体对齐后的 ATE 1.3 → 0.4 cm；图优化 48 → 18 s |
| 测量点云（L 类） | 体素内与最近观测距离相当的观测按 1/σ² 加权平均；每点带沿法向的 σ（观测离散 / √n 与形式误差取大，加 3 mm 底） | 表面误差中位 1.0 → 0.2 cm，p95 2.5 → 1.6 cm；79% 的误差在 1σ 内、94% 在 2σ 内 |
| 手持真值导入与报告 | 读 PLY / LAS / PCD / XYZ / NPZ 与标注；重力对齐粗配准 + ICP；控制点数据基准；柱检查点在地图点上量测；表面精度、分高度带完整度、矢量、结论，中文报告 | 第 1–2 步 3/4 项通过（车位角点未过），第 4 步 4/4 通过 |
| 正射影像上的矢量拟合 | 在亮度图上亚像素重测车位线：剖面半亮度边缘定中心线，沿线半亮度交点定端点，端点外侧地面可见才算可靠；排的入口 / 后端取可靠端点中位数，看不到的一端按实测车位深度补齐；柱面在点云上拟合 | 车位角点 RMS 5.7 → 1.7 cm（CE90 7.5 → 2.5 cm）；语义柱心 7.9 → 2.0 cm |

几点结论：

- **扫描到地图精修会收敛到自洽但有偏的解**：坡道折线处的局部平面混合了地面和坡面，坡度被"拉平"约 0.05°，两层高程差约 2 cm；只看地图厚度、回环残差等内部指标发现不了，要靠手持真值或控制点。
- **刚性的地图会放大锚点的错误**：BA 后整张图像一块刚体，入口锚点的时间戳错误（INS 位姿早于第一帧 0.1 s、第一帧没去畸变、早于第一帧的 GNSS）不再被局部吸收，而是把整张图转偏 0.2°。修法：锚点带时间戳，用轮速 / 陀螺推到关键帧时刻；连续轨迹首尾外推。
- **绝对坐标要靠控制点**：车辆坐标系的绝对位置只由入口锚点决定（这里约 1.5 cm、0.03°）。测量级成果按测量惯例先用控制点定坐标系，再看检查点。
- **相机正射影像的分辨率决定能否用它拟合矢量**：256 px 鱼眼的正射影像比 LiDAR 强度图模糊（中心线 RMS 3–4 cm 对 1 cm），目前默认先用 LiDAR 强度。第 3 步的 3DGS 正射影像或高分辨率相机应改为相机优先。
- **还没解决的**：
  - LiDAR BA 的稠密位姿块适用于约 2500 个关键帧以内，更大的车库需要分层 BA；
  - 手持真值目前是模拟的；真实项目要在手持点云上数字化柱、车位、标线作为检查要素；
  - 入口线被遮挡多的排只有很少的可靠端点（small 数据里有一排偏 4–5 cm）；
  - 3DGS 的 G 类点与核验属于第 3 步；LiDAR–IMU 外参仍未估计。

### 10.3 进度（2026-10-15）：导航语义、车位号、车位检测的真实数据修正

| 项 | 做法 | 结果 |
|---|---|---|
| 导航地图（`nav` 阶段） | 见 4.6；距离变换、骨架提图、最短路、栅格 A* 在 C++（`nav_map`） | 合成 small：60/60 车位可达，路线碰到障碍 0 条，最小间距 1.25 m，两层经坡道连通；室外停车场 79/81；地下车库 36/37 |
| 车位号（`numbers` 阶段） | OCR 文字的像素射线落到地面、按车位投票，同排编号连续修正 | 合成数据（真值 OCR）60/60 分区与编号正确；真实数据未接 OCR 模型 |
| 车位检测（真实数据） | 逐排估计方向；背靠背判断用端点分位数；推断车位要有遮挡或油漆证据，开过、重叠、落在未观测区域的不推断 | 室外停车场 300 个（223 个推断，大多铺进车道）→ 81 个，与画线吻合；合成数据角点误差不变（2.24 cm） |
| 3DGS 支撑（C++） | 见 3.4 补充 | 单元测试通过；训练待 GPU |

几点结论：

- **障碍要按几何判定，再用语义分层。** 语义误分（墙被标成其他类）不能让路线穿墙；无类别点要按观测次数过滤，否则移动目标的残留点会在车道里造成假障碍。
- **真实场地的车位检测是导航的瓶颈。** 推断车位不加约束时，会在空车道里和垂直方向上铺出大量假车位，把车道切断；车道、目标点都依赖车位层的质量。
- **各排车位的方向常与全局网格差 1–2°。** 长排会因此被误判为背靠背双排或深度超限；逐排估计方向要有显著性门槛，否则端点噪声会把对齐的排转偏（合成数据上角点误差从 2.2 cm 变成 2.9 cm）。
